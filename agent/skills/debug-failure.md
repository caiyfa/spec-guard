## 失败分析技能

### 分析流程

1. **读取报告**：使用 `read_run_report` 读取最近的运行报告
   - 提取失败场景列表
   - 获取每个失败场景的断言差异和环境探测结果

2. **读取场景**：使用 `read_scenario` 读取失败场景的 YAML 内容
   - 分析 flow 步骤和 verify 断言
   - 检查 save 变量和插值路径

3. **读取需求**：使用 `read_spec` 读取相关需求文档
   - 确认预期行为与实际结果的差异

4. **DB 证据**：使用 `db_evidence` 查询数据库状态
   - SQL 必须为 SELECT/SHOW/DESCRIBE/EXPLAIN（只读）
   - 校对断言时的数据库实际状态

5. **根因分析**：综合以上信息判断失败原因
   - 数据问题：测试数据缺失或不符预期
   - 环境问题：网络/DB/SSO 不可达
   - 场景问题：YAML 逻辑错误、断言条件错误
   - 权限问题：账号无权限访问目标资源

6. **修复建议**：给出具体的修复方案
   - 指明需要修改的 YAML 行号和修改内容
   - 如果是数据问题，说明需要准备什么测试数据
   - 如果是环境问题，说明 SKIP 语义（不报 FAIL）

### SKIP vs FAIL 语义

- **SKIP**：测试数据缺失/账号未配置 → 环境问题，不报 FAIL
- **BLOCKED**：上游场景失败 → 依赖问题，不报 FAIL
- **FAIL**：断言不通过 → 真正的测试失败

绝不能把环境问题报成 FAIL。
