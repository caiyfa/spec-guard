# SpecGuard Vision · 汇报演示原型设计基线（构建任务书）

## 使命
为「SpecGuard 远期完整版 / 完整 spec 工作流」构建一个**给领导汇报演示**用的交互式原型。
现有 V4 原型（`/mnt/agents/upload/specflow需求侧交互原型.html`）被用户否定：太像工程工具、缺叙事、不像汇报演示。
新原型 = **发布会级叙事开场 + 精修的产品形态屏**，演示者可以照着"汇报提示"一路讲下去。

## 交付物
- 单文件：`/mnt/agents/output/specguard-vision/index.html`
- 零外部依赖（无 CDN、无 npm；字体用系统栈；图表全部内联 SVG/Canvas）
- 浏览器直接打开即可演示；16:9 投影与笔记本屏均可读

## 必读素材（构建前先读）
1. `/mnt/agents/upload/specflow需求侧交互原型.html` —— V4 原型。**复用其中的真实业务数据**：真实 FR 锚点、场景 ID（如 PP-RC-005）、场景库、面试会话脚本（IV-/D-/SPQ- 编号）、决策台账条目、五维评分数据、DAG 批次、里程碑（init/refactor/es-acceleration/smart-tag）、图谱数据（28 功能 · 298 FR · 25 场景 covers）。**数据必须真实继承，禁止编造新 ID。**
2. `/mnt/agents/upload/需求侧Spec工作流体系设计方案-specflow.md` —— 设计方案，叙事内容来源（已拍板决策、双体系分离、血缘链 §4.7、图谱 §4.6、路线图第五章）。

## 视觉方向（与 V4 拉开代差）
- 高级暗色（Linear/Vercel 质感）：底 #08090c / #0d0f14；卡片 rgba 微光；细分隔线 rgba(255,255,255,.06)；柔和投影；微噪点/网格背景仅叙事屏使用。
- 身份色体系沿用方案：需求侧=紫 #a78bfa，测试侧=青蓝 #5ec8f2；状态色 绿/黄/红 低饱和。
- 字体栈：-apple-system / "SF Pro" / Inter / PingFang SC / Microsoft YaHei；等宽 JetBrains Mono fallback。
- 叙事屏（S0-S2）大字号、大留白、发布会排版；产品屏（S3-S7）精致紧凑但比 V4 更透气。
- 动效克制：入场淡入上浮、hover 微浮起、使命卡片流光描边可保留但降速降亮。

## 屏结构（8 屏 + 顶部原型导航）
顶部导航条：SpecGuard · Vision 原型徽标 + 8 个屏切换 tab + 右侧「汇报提示」开关 + 「◀ 上一步 / 下一步 ▶」演示动线按钮。

### S0 封面
项目名、定位一句话「需求 → 验证 全链路质量平台 · 远期完整版交互原型」、日期 2026-07、汇报人占位、"开始演示 →"按钮跳到 S1。背景用极淡的血缘链环线装饰。

### S1 价值总览（叙事核心）
- 中央：**五环大循环图**（SVG 环形）：需求面试(P0清零) → spec冻结(三闸) → 场景生成 → 执行归因 → SPQ反哺 → 回到需求面试。每环 hover 显示一句价值说明。
- 下方或侧边三个要点卡：① 上游 spec 质量不受控是现状痛点；② 双体系分离（.specflow 需求侧 / .specguard 测试侧，两个界面产物：冻结 spec 基线 + delta 变更）；③ 反哺闭环是引入需求侧后才真正闭合的大循环。
- 关键数字条：28 功能点 · 298 FR · 25 场景 · 5 阶段路线。

### S2 路线图
- 横向时间线/泳道：F1 面试最小闭环 → F2 扫描仪与评分卡 → F3 锚定与归档 → F4(V2候选)；下方并行支线 G1 → G2 → G3（知识图谱）。
- 标注「F1 = 价值拐点」；每阶段卡片含：内容、触层、门禁/评审要求（取自方案第五章表格）。

### S3 新建会话 · 使命卡片
- 沿用已拍板方案 A：两张使命卡并排悬浮（需求面试=紫 / 测试工作台=青蓝），hover 浮起+流光描边+3D 微倾斜，**单击卡片直接进入对应会话屏**（S4 / S5）。
- 副标题固定一行：「点击卡片直接开启会话 · 用途创建后锁定，不可中途变更」。
- 键盘流提示：←/→ 切换、Enter 开启（可真实实现）。

### S4 需求面试会话（产品屏，紫色身份带）
三栏：会话树（左，按用途徽标过滤）/ 聊天区（中，真实面试对话脚本：AI 面试官提问 → 产品拍板 → 决策结构化入台账，至少 6 轮，用 V4 真实脚本）/ 右侧面板**五页签**：
1. 材料包（议题卡 + 基线摘录 + 未闭环 SPQ + 上轮报告摘要 + 历史决策）
2. 决策台账（P0/P1/P2 条目 + pending/resolved 状态机 + P0 清零门禁面板）
3. 五维评分（SVG 雷达图：逻辑完整性/预期清晰度/覆盖率/边界异常/前置条件，总分 ≥70 及格线标注，LLM 预打分 + QA 确认语义）
4. spec 草案（等宽代码风，FR-xxx 锚点高亮、「待确认」TBD 标记）
5. 影响面（小图谱：议题候选 FR → 受影响节点变色脉冲，挂「P0 影响面人工确认」动作按钮）

### S5 测试工作台会话（产品屏，青蓝身份带）
同三栏骨架，右侧**四页签**：
1. 覆盖缺口（FR 覆盖矩阵/缺口清单，无覆盖红/有覆盖绿/草稿待审黄，挂「生成下一批」按钮）
2. 草稿三闸（人工评审 → 格式校验 → 发布门禁 三道闸状态 + YAML 预览）
3. DAG 批次（delta 导入的计划 DAG 图，批次分层）
4. 报告→SPQ 反哺（执行报告摘要 → SPQ 条目生成 → 入 info_pack 提示「将成为下轮面试素材」，点击可跳 S4 暗示闭环）

### S6 血缘链 Story Line（叙事+产品混合）
- 横向/环形链路：面试 IV-xxx → 决策 D-xxx → 冻结 delta → FR-xxx →【外部锚点：禅道 task / PR / 单测】→ 场景 PP-RC-005(covers FR) → 计划 plan_id → 报告 run_id → SPQ-xxx → 入 info_pack → 回到下轮面试。
- 每节点可点击，点击后下方/侧边显示该节点详情卡；断链节点灰色虚线示例一个。
- 两个审计问题作为讲解锚点：「这个场景为什么存在」（向上追溯）/「这个需求被验证了吗」（向下追溯）。

### S7 全景图谱
- L0 模块星座图（模块级聚合，边粗=耦合强度）→ 点击模块进入 L1 模块内功能点 → 点击功能点进入 L2 FR 邻域聚焦；面包屑返回。三套配色语义切换：覆盖状态 / 变更影响 / 面试焦点。
- backlink 面板：点 FR → 「哪些场景覆盖我 / 哪些 delta 改过我 / 哪些决策引用我」（计算型、只读）。
- 底部里程碑时间轴滑块：init → refactor → es-acceleration → smart-tag，拖动切换快照，支持 diff 视图（新增绿/消失红空心/变更黄）。
- 全景三职责入口提示：面试选题 / 测试债地图 / 新人 onboarding。

## 汇报提示（每屏一段，可开关）
顶部「汇报提示」开关打开时，每屏顶部出现一条演示者讲解词（2-3 句，口语化、面向领导、突出价值），例如 S1：「这一屏回答一个问题：我们为什么要从测试工具扩张成全链路平台——因为 spec 质量不受控，下游全部带病工作……」。8 屏各写一段。

## 硬性约束
- 单文件、零外部请求（不引用任何 http(s) 资源）。
- 全部数据 ID 从 V4 原型继承，不新造。
- 中文界面。
- 代码组织清晰、有注释；JS 用原生 ES6+。
