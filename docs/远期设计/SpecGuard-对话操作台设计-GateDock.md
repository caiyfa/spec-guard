# SpecGuard 对话操作台（GateDock）设计

> 状态：待评审 · 2026-08-13
> 来源：菜单面板（材料管理/评分冻结/禅道集成）与 Agent 对话面板的融合探讨，经两轮澄清定界后成文。

---

## 1. 背景与问题

S3/S4/S5 三个人拍板面板已前后端齐备（T-058/T-059 前端补丁、M06 禅道集成），但使用动线断裂：

- 材料 → 评分 → 冻结 → 禅道交付是一条连续工作流，却散落在三个独立菜单页签；
- 使用者在 AgentChat 与菜单面板间反复横跳，新用户面对面板不知道"当前该做什么"；
- 各阶段有使用门槛：材料状态机、三闸语义、禅道作业/锚点概念都需要学习。

**目标**：以对话面板为统一操作台，把三个面板的单条拍板动作收进对话上下文，人点按钮完成操作；Agent 作为引导员与兜底，降低各阶段使用门槛。

## 2. 设计原则与已定边界

经探讨确认的两条边界（本设计的硬约束）：

1. **不是 Agent 对话驱动执行**。操作仍由人点按钮，走原有 REST + RBAC；不新增任何 MCP 写工具，禅道写操作的铁律 1（Agent 只建议、人拍板）原封不动。
2. **分档接管**。每个操作卡配「🤖 帮我」按钮，Agent 接管深度按操作性质分档（见 §5），定性决策的最后一下永远人点。

已否定选项（探讨中排除，留存备查）：

| 选项 | 否定理由 |
|------|----------|
| Agent 全量对话驱动执行（新增 MCP 写工具） | 触碰铁律 1；幻觉 → 禅道脏数据；闸门架空 |
| 菜单全撤、对话唯一入口 | 闸门失去审慎空间；对话上下文错绑风险；列表/台账类管理视图在对话侧栏体验差，操作卡无法 100% 接管 |

## 3. 信息架构：双入口，菜单降级不撤

```
日常操作主入口                     管理/审计入口（保留）
┌─ AgentChat ─────────────┐      ┌─ 需求分组（折叠） ────────┐
│ 对话流：Agent 到节点推卡   │      │ 材料管理（列表/台账/批量）  │
│ 侧栏「操作台」页签：       │      │ 评分冻结（评分历史/闸记录） │
│  聚合当前上下文待办闸门卡  │      │ 禅道集成（作业/锚点/审计）  │
└─────────────────────────┘      └──────────────────────────┘
```

- **对话流推卡**：Agent 感知阶段状态，在流程节点主动推送操作卡（assistant 消息携带 card payload，references 机制已有同类扩展先例）。
- **侧栏操作台页签**：与待办/信息包/草稿页签并列，聚合当前会话上下文的全部待办闸门卡片；不依赖 Agent 推送，用户随时可进。
- **菜单面板降级**：三个页签保留，折叠为「需求」分组下的管理视图，承担列表、台账、批量、审计职能——单条拍板的日常动线在对话，表格类管理仍在面板。

## 4. GateCard 统一组件

```
┌─ 📦 材料入包 ───────────────────┐
│ 会议纪要-0728.md · 已解析          │
│ 2 个议题候选待确认                 │
│ [入包] [查看候选] [🤖 帮我]        │
└──────────────────────────────────┘
```

- 每张卡 = 类型图标 + 状态摘要 + 操作按钮组 + 「🤖 帮我」。
- 操作按钮**直调原有 REST**（材料入包/议题确认/评分确认/三闸/冻结/建故事/提 BUG/故事点回写），带现有 RBAC；后端写接口零改动。
- 「🤖 帮我」复用 WritingPanel 的 `askAgentFix` 模式：往对话发一条结构化请求，携带操作类型 + 对象 ID + 当前状态摘要。
- GateCard 同时用于两个载体：对话流内嵌（消息 card payload）与操作台页签（列表渲染），同一组件两种容器。

## 5. 分档接管矩阵

| 档位 | Agent 行为 | 适用操作 |
|------|-----------|----------|
| L1 引导 | 解释当前状态、教学（"这份材料已解析，点'入包'即可"） | 全量操作的兜底 |
| L2 预填 | 预填参数（故事标题、BUG 严重度、复现步骤）+ 高亮待点按钮 | 评分确认、冻结三闸、禅道建故事/回写/提 BUG |
| L3 代执行 | 经用户确认后，以前端用户身份调原有 REST 直接完成，对话回显结果 | **仅白名单**：材料入包/移出、议题候选确认（均可逆、低危） |

约束：

- 评分确认、冻结、禅道写操作**永远停在 L2**——这些是定性决策，闸门意义即人拍板。
- L3 代执行走前端用户身份的原有接口，权限由现有 RBAC 兜底，不绕三道闸。
- 白名单后续扩缩需评审，比照引擎冻结层语义变更流程。

## 6. Agent 主动推送

| 触发节点 | 推送卡片 |
|----------|----------|
| 材料解析完成（parsed/indexed） | 议题候选确认卡 |
| 议题确认完毕 | 材料入包卡 |
| 机器评分完成 | 评分 QA 确认卡 |
| 三闸全过 | 冻结确认卡 |
| delta 冻结完成 | 禅道建故事卡（含 L2 预填标题） |
| 禅道 BUG 回查 resolved/closed | 回归建议卡 |

支撑改动：

- **后端新增只读接口**：`GET /api/specflow/gate-dock?workspace=&interview_id=` 返回当前上下文待办闸门汇总（供操作台页签与 Agent 推送共用数据源；纯读，符合"校验/查询不写副作用"约束）。
- **Agent 侧**：system prompt / skills 增加操作台引导知识（各闸门语义、推卡时机、L1 话术）；Agent 经现有只读工具 + 上述汇总接口感知状态。
- **前端**：assistant 消息支持 card payload 渲染 GateCard。

## 7. 分期实施路径

| 期 | 内容 | 改动面 |
|----|------|--------|
| 一期 | GateCard 组件 + 操作台页签 + 三面板单条拍板动作收编（人点按钮）+ 帮我按钮（L1 引导）+ 只读汇总接口 | 前端为主 + 1 个只读接口 |
| 二期 | 对话流主动推送（card payload）+ L2 参数预填 + Agent 引导话术进 skills | 前端 + agent/skills |
| 三期 | L3 白名单代执行（材料入包/移出、议题确认） | 前端（前端身份调原接口） |

每期独立可交付、可回退：一期上线即得"统一入口"收益；二期得"丝滑"收益；三期得"兜底"收益。菜单面板全程保留，验证对话覆盖率后再议是否进一步折叠。

## 8. 风险与回退

| 风险 | 缓解 |
|------|------|
| 对话上下文错绑（操作对象张冠李戴） | GateCard 显式标注对象 ID/名称；按钮二次确认；操作台页签数据源按会话上下文过滤，无上下文时显示空态引导 |
| 操作卡覆盖率不足导致能力回退 | 菜单面板保留，任何场景可回退到原面板 |
| 推卡打扰 | 推卡只在状态迁移节点触发，同节点同对象幂等不重复推 |
| L3 代执行被误扩大 | 白名单硬编码在前端常量，扩清单需改码评审 |

## 9. 验收要点（一期）

- 操作台页签能聚合当前 interview/delta 上下文的待办闸门卡，按钮操作与原面板效果一致（同一 REST）。
- 「🤖 帮我」触发对话内 L1 引导，Agent 能正确解释该闸门语义与下一步。
- 菜单三面板功能无回退；`python release_check.py` 全 PASS；前端 `npm run build` 通过。
