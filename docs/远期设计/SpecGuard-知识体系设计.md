# SpecGuard 知识体系设计（远期）

> 版本：v1.0 · 2026-08-07 ｜ 状态：设计定稿（待总控评审）｜ 配套：《SpecGuard-deepferry借鉴勾稽表》、模块设计 M03/M09/M11/M13
> 定位：回答「SpecGuard 的知识怎么管」——现状工作区 = spec 文档仓库，无语义词典、无环境叙事、无经验自动积累；本设计给出五层模型 + 隔离机制 + 触景触发引擎 + 维护页 + 入口管线。
> 设计来源：deepferry 知识库体系（knowledge.py / memory.py / openspec glossary）移植设计思想，按 SpecGuard 领域对象（FR 锚点/场景/环境/资源码/SPQ）与 8 铁律重写，**不引代码依赖**。

## 1. 现状与三条硬约束

**现状**：知识只有三处——规则层（工作区 AGENTS.md 全量注入 system prompt，P1 决策：规则层不允许有损压缩）、人工经验包（docs/经验包五段式）、SPQ 台账（feedback/ledger）。缺：语义词典（业务术语机器可查）、环境叙事（各环境「是什么/有什么坑」）、经验自动积累（debug-failure 每次从零排查）。

**三条硬约束（总控人拍板）**：

1. **语义按系统/工作区隔离**——不同系统、不同工作区知识点不同、语义不同，不得混杂
2. **知识触景出现**——恰当的时候出现在恰当的地方，不堆提示词
3. **提示词瘦身**——当前 system prompt 静态部分约 75 KB，必须减

**设计原则**：入口自动化、生效人工闸（铁律 1）；触发规则确定性、不用 LLM 路由（铁律 2）；注入预算硬顶；知识索引是派生物非事实源（M11 同哲学）。

## 2. 五层模型

| 层 | 内容 | 载体 | 状态 |
|---|---|---|---|
| **L0 规则层** | 工作区 AGENTS.md | 工作区仓库，全量注入 prompt | 已有，**不动**（P1） |
| **L1 语义词典** | 业务术语/资源码/环境键的机器可读词条 | 工作区仓库 `glossary.md`，随 spec 同库同评审 | 新建 |
| **L2 环境叙事** | 各环境「是什么/拓扑/账号池/已知坑」 | `systems/{system}/config/env.{env}.md` 伴随文件 | 新建 |
| **L3 经验飞轮** | agent 运行经验自动积累 + 人工经验包 | 工作区 `.specguard/experience/` + docs/经验包 | 新建（S6） |
| **L4 触景分发** | 触发式知识寻址与投递引擎 | runtime 工具包装层 + 消息入口 | 新建（S3） |

### 2.1 L1 语义词典（glossary.md）

- **词条格式**（deepferry 七维适配）：精确语义 / SHALL 规则 / 数据维度 / **关联 FR 锚点 + 场景 ID + 资源码/env 键** / 歧义史 / 关联文档代码；带 `[token: xxx]` 锚点（specstd/anchors 同款正则解析）
- **收录标准（防膨胀）**：被 ≥2 个 FR 或场景引用、背后挂业务规则、有歧义史——三者满足两条才收（如「盘点会话」「快照冻结」「资源码 TDM_INV_ACTIVITY」）
- **比 deepferry 狠的一点**：词条引用的 FR 必须存在——「词典↔Spec 关联完整性」纳入 specstd conformance / release_check 代码化校验（deepferry 的 glossary 只是文档约定）
- **治理**：人工策展落锤；Agent 只提议不回写（提议进待确认队列）；staleness 复用 specstd/signature 指纹

### 2.2 L2 环境叙事（env.{env}.md）

- 内容清单：环境定位 / 网关与 DB 拓扑 / 账号池角色表 / 资源码清单 / **已知坑**（如 EX-8200eada 的 TDM_INV_ACTIVITY 未授权）/ 数据重置周期
- **红线**：叙事层永不写凭据（凭据仍走 env yaml + devops 回退）
- 补上 T-309 通用/系统分层后的叙事空缺；与 EnvironmentConfig 页职责分离（那里管结构化 yaml，这里管叙事）

### 2.3 L3 经验飞轮（deepferry memory.py 移植）

- **双轨制**：自动层（会话/run 终局落行 success/failed/corrected + 用户纠正关键词检测 + 后台 LLM 富化 lesson + recency×hit_count 检索）+ 人工层（现有 docs/经验包五段式）
- 分层哲学：自动层是素材池，反复命中的由人提炼为经验包（对应 deepferry「经验提炼为 skill」）
- 入口零人力；纠偏机制：未验证标记、命中数佐证、👍/👎 反馈、摘要带置信状态
- 存储按工作区隔离（`.specguard/experience/`），contextvar 透传复用现有链路
- 消费点：debug-failure 技能、M09 归因 Agent 证据包

### 2.4 L4 触景分发

详见 §4。没有这层，L1-L3 是死文档——**分发机制是知识体系的灵魂**。

## 3. 三层物理隔离（约束①）

| 归属层 | 位置 | 内容 | 生命周期 |
|---|---|---|---|
| 系统层 | `systems/{system}/` | env.{env}.md、资源码/账号池语义 | 随适配包 |
| 工作区层 | spec 仓库 | glossary.md、AGENTS.md | 随 spec 同库同评审 |
| 运行态层 | 工作区 `.specguard/` | 经验库、info_pack、知识索引缓存（派生物） | 运行产物 |

- 知识加载器只从「当前激活工作区 + 当前系统适配包」两个根解析路径——**无全局知识目录，物理上不存在混杂通道**
- 复用 specstd workspace contextvar 全链路透传（前端 X-SG-Workspace header → agent/MCP/covers）；MCP stdio 走 SG_WORKSPACE
- 同名 token 在两个工作区各自解析（语义本就工作区局部，是特性不是 bug）
- 对外开放面（M13 dev_context pack）的「术语摘录」分区从当前工作区词典取，L0 只读面按工作区隔离

## 4. 触景触发引擎（约束②）

### 4.1 寻址与索引

- 寻址格式：`kg://{workspace}/{layer}/{token}`（layer ∈ term/env/experience/pack/skill）
- 加载期从词典 frontmatter / 经验库 / SPQ 台账构建**触发索引**（token → 触发条件 → 摘要），确定性派生、指纹失效即重建；30s TTL 热加载（复用 mode_loader/skill_loader 模式）

### 4.2 匹配通道（双通道，收窄设计）

| 通道 | 匹配方式 | 取舍 |
|---|---|---|
| **工具调用/结果（主）** | 解析结构化字段（scenario_id→模块、错误 category/message、preflight 缺口键名），非文本扫描 | ✅ 精确零歧义 |
| **用户输入（辅）** | 自由文本多模式匹配（Aho-Corasick）词典 token 与别名 | ✅ 容错高 |
| **agent 自身输出** | — | ❌ 不做：回环风险（提到→注入→更频繁提到）；无价值（已知的不需浮现）；deepferry 亦为绑定制非输出扫描 |

### 4.3 投递与预算纪律

- 投递点：工具结果尾部 `<knowledge_refs>` 块（挂 T-403 已建的 runtime 统一出口）+ 用户消息入口；归因时相关经验直接进证据包；会话创建时仅投「本工作区知识目录」（几百字符，不含内容）
- **预算硬顶**：每篇每会话最多 nudge 一次（已读集合去重）；nudge = ≤400 字符摘要 + `read_knowledge(ref)` 指针；每会话知识注入总量 ≤4KB；多命中按优先级截断（错误签名 > 显式 @ > 工具绑定 > 关键词）
- **误报免疫**：误命中代价 ≈ 一行指针，agent 不相关则不取正文——不会像全文注入污染上下文

### 4.4 性能论证

- 匹配开销微秒级（AC 自动机数百 pattern × KB 级文本），对秒级 LLM 延迟淹没；进程内同步 hook + 内存索引，无 I/O
- **真正的成本是 token 预算，不是 CPU**——§4.3 纪律是机制核心

### 4.5 面板呈现（依据透明 · 阅读足迹，S0.5 快车道）

触景分发不只有「推给 agent」，还有「**摊给用户看**」——依据透明是透明度体系的第三层（待办=进度透明、草稿产物=结果透明、阅读足迹=依据透明）。现状缺口实锤：工具组折叠后用户只剩「7/7 工具」+ 一行摘要（`AgentChat.tsx:368` 注释：生产会话 100 轮工具调用全部不可见）。

**分层实现**：

| 层 | 内容 | 改动面 |
|---|---|---|
| **V1 阅读足迹面板**（S0.5 · T-511） | runtime 调读完型工具后发 WS 事件 `doc_read`（path/tool/turn/头部摘要/大小）；右侧新增「📖 阅读」页签：时间倒序文件卡片（路径+工具+头几行摘要），同文件去重合并；**点击打开 `file:` 页签即定位**（locate 行区间参数 + 范围高亮） | runtime + AgentChat 页签；**零工具改动** |
| **V2 关键章节提取**（S0.5 · T-512） | `read_spec` 加可选参数 `anchor`/`section`：md 按标题树、FR/AC 锚点走 specstd/anchors 现成解析；场景 YAML 提取 covers/关键步骤；报告类直接展示失败断言段。面板卡片升级为「命中章节标题+段落摘要」；**多处 hunk 导航 + 意义标注**（见下） | spec_reader + 面板卡片；顺带治 `read_spec` 整文件读取（200KB 截断）的 token 浪费 |
| **V3 交互反哺**（可选，挂 T-510） | 用户 pin 章节 → `@references` 机制注入下条消息；划词「这段不对」→ 纠正检测联动经验飞轮 | 前端 + T-510 |

**定位与多处导航（V1.5 澄清，2026-08-07 总控人指令）**：

- **打开即定位**：`file:` 页签加 locate 参数（行区间），打开后滚动到位并高亮；渲染侧加行号 + 行区间高亮（纯前端增强）
- **多处 hunk 导航（git-diff 式）**：数据模型 = 一文件一卡 N 个使用位置（hunk）；同一文件多次读取的不同章节各自成 hunk，文件页签顶部导航条「▲ n/N 处 ▼」跳上处/下处并各自高亮。hunk 行区间来自 V2 章节提取返回的 {章节标题, 行区间, 摘要}——V1 阶段每卡单 hunk（全文/头部），V2 落地后导航自动出现
- **意义标注（确定性双来源，无 LLM 总结）**：① 工具名+关键参数（结构化：`read_spec(anchor=FR-009)` →「引用需求条目 FR-009」；`read_run_report(case=PP-RC-005)` →「查看失败断言差异」）② K-024 思考文本（agent 调工具前的 1-2 句理由，`doc_read` 事件捎带最近一条）。每个 hunk 头部标注条：`FR-009 · read_spec · 第3轮 · 💭 确认权限过滤规则`——用户扫一眼就知道 agent 为什么看这段

**边界纪律**：只对读型文档工具（read_spec/read_scenario/read_run_report/read_run_log/read_info_pack）；写型/查询型工具不上面板；excerpt 预算与 T-403 截断同口径（宁少勿多）；常驻 prompt 的 AGENTS.md/format_spec 不进足迹（它们不是 agent「读的」）。

**底座复用**：右侧面板页签体系（待办/信息包/草稿/依赖图/文件页签）、`onViewFile` + `file:` 页签全文预览、工具结果摘要渲染——全部现成，新增的只是「自动汇聚」。

## 5. 提示词瘦身（约束③）

### 5.1 现状量化（2026-08-07 实测）

| 组成 | 大小 | 说明 |
|---|---|---|
| format_spec | ~26 KB | 全量常驻（K-023 决策） |
| 工作区 AGENTS.md | ~22 KB | P1 决策全量注入 |
| skills 5 个全文 | ~16.4 KB | build_skills_xml 全量进 `<skills>` |
| modes 任务指引 | ~13 KB | K-023 后仍按条件段落注入 |
| 模板固定文本 | ~3 KB | 角色/硬约束/输出格式/待办 |
| **合计** | **~75 KB** | 静态部分 |

### 5.2 方案（两档，**待总控评审定档**）

| 组成 | 激进档（推荐）~30 KB | 保守档 ~52 KB |
|---|---|---|
| format_spec | **骨架常驻**（章节索引+双层结构+硬约束+tool/oracle 目录，~4 KB）+ `read_format_spec(section)` 工具按需取细节 | 维持全量常驻 |
| AGENTS.md | 22 KB 不动（P1） | 同 |
| skills | 目录常驻（name+description，~0.6 KB）+ `load_skill` 取正文（M13 T-080 前置） | 同左 |
| modes | 并入 skills 目录（任务指引本质是 skill，合并去重） | 同左 |
| 新增知识层 | 零增长（全走 §4 消息流触景） | 同左 |

- 激进档与 K-023 的关系：K-023 反对的是「条件注入=路由复杂度回潮」——骨架方案是**固定注入**（无路由），prompt cache 前缀照样命中，两点不冲突；真实代价 = 生成场景前需 `read_format_spec` 取细节章节（多一次工具调用），由 generate-scenario 技能正文指引 + validator 硬约束兜底
- **推荐激进档**，但涉及 K-023 决策修订，列为评审点

## 6. 知识维护页（一页三区）

单一菜单项「📚 知识」（遵守单一菜单树纪律，不每类一页）：

1. **词条**：列表（关联 FR/场景计数、staleness 标记）+ Monaco 编辑；**保存即校验**——FR 断链标红、收录标准警告（复用 specstd conformance 通道）
2. **环境叙事**：env.{env}.md 编辑 + 与 EnvironmentConfig 页双向链接；凭据红线提示
3. **经验审核**：队列列表（outcome/命中数/最近命中）+ 👍/👎 + 「提炼为经验包」（生成五段式草稿走既有流程）+ 停用

纪律：RBAC 写权限 + 审计留痕；**Agent 提议以「待确认」进队列，人落锤才生效**（铁律 1 的 UI 体现）。不做：富文本、知识大屏（归 M11 图谱页）、nudge 规则配置页（代码事）。

## 7. 知识入口四条管线（入口自动化，生效人工闸）

| 管线 | 机制 | 人力 |
|---|---|---|
| ① 冷启动引导 | Agent 辅助批量提取（spec FR/AC + 场景 + env yaml + 经验包 + 排障记录）→ 候选草稿 → 审核队列 | 一次性半小时批量确认 |

## 9. 治理纪律（8 铁律对齐）

1. Agent 只提议不回写；人拍板落锤（铁律 1）
2. 触发规则、关联校验、staleness 全走确定性机制，无 LLM 路由、无向量库（铁律 2）
3. 词条/叙事内容落 git 版本化；运行态经验按工作区隔离不入 git
4. 知识索引 = 派生物非事实源，指纹失效即重建（M11 三红线同款）
5. 叙事层永不写凭据；对外开放面只读、按工作区隔离
6. 注入预算硬顶：L0 之外无全量注入，一切按需+触景
