# 外部生态扫描简报——AI Agent Skills & MCP 生态成熟度（截至 2026-07）

## ① Agent Skills 生态成熟度

**事实（有来源）：**

- **规范已成跨厂商事实标准。** Anthropic 于 2025-10 推出 Agent Skills，2025-12-18 以开放标准发布于 agentskills.io，由 Agentic AI Foundation 托管。截至 2026-06，约 40 个平台支持（Claude、OpenAI Codex、GitHub Copilot、VS Code、Cursor、Gemini CLI、Goose、Databricks、Snowflake 等）。
  来源：https://agentman.ai/blog/agent-skills-ecosystem-report-2026 （2026-06-24）
- **格式与 SpecGuard 高度同构。** 规范最小要求仅为 YAML frontmatter 的 `name`（≤64 字符、须与目录名一致）+ `description`（≤1024 字符）+ Markdown 正文；可选字段 `license`、`compatibility`、`metadata`（author/version）、`allowed-tools`（实验性）；未识别字段须被 runtime 忽略。加载采用三级渐进披露（frontmatter ~100 tokens → 正文 <5000 tokens → references/ 按需）。规范明确警告 frontmatter 中勿用 `<>`（注入风险）。
  来源：https://agentman.ai/blog/build-your-first-agent-skill-skillmd-anatomy （2026-06-09，转述 agentskills.io 规范）
- **`version` 字段尚未进规范。** SemVer 版本字段仍是讨论中的提案（2026-06），规范的供应链信任/验证指导也是开放 issue（#418）——**签名、lockfile、版本 pinning 协议均不存在**，需自建。
  来源：https://github.com/agentskills/agentskills/discussions/420
- **公开仓库/市场层次丰富但无官方权威注册表**（对比 MCP Registry）：anthropics/skills（官方，>150k stars）；Vercel 的 skills.sh（可搜索目录+安装量排行，事实上的分发中心，`npx skills add` 为通用安装方式）；awesome-claude-skills（13k stars）、appssemble/awesome-skill-md（列出 google/skills、huggingface/skills、cloudflare/skills、hashicorp 等十余家厂商官方 skill 仓）；obra/superpowers（40.9k stars 社区最大集合）；还有带审计评分的第三方注册表 openagentskill.com（readiness/trust/audit 打分）。
  来源：https://www.firecrawl.dev/blog/best-claude-code-skills （2026-07-20）、https://github.com/appssemble/awesome-skill-md、https://www.openagentskill.com
- **质量与安全数据偏负面。** 2026 年审计在被测 skill 中发现 36% 含 prompt injection；SkillsBench 显示公开 skill 平均质量 6.2/12，仅 top-quartile 真正提升 agent 表现（精选 skill 平均提升 16.2 分）；部分注册表扫描器对合法包误报 warn 达 ~42%。
  来源：agentman.ai 报告（同上）、https://www.manifold.security/blog/ai-agent-skill-registry-supply-chain-security （2026-04-22）
- **企业治理实践（推断+零散事实）：** 业界共识做法≈"把 skill 当开源依赖管"：安装前审查源码、沙箱试跑、只装精选/厂商官方 skill；尚无成熟的签名/认证体系。出现 `moonrunnerkc/skillcheck` 这类 frontmatter 校验+描述可发现性评分+token 预算检查的"质量门"工具——**这恰好是"skill 审查管线"的参考实现雏形**。
  来源：https://github.com/appssemble/awesome-skill-md（列表内条目）

## ② MCP 生态成熟度与治理实践

**事实：**

- **官方 Registry 已上线。** registry.modelcontextprotocol.io 2025-09 预览上线，存 `server.json` 元数据（不存代码）、支持 GitHub/DNS 命名空间验证。至 2026-05 官方收录近 2000 个 server；社区目录口径 20,000+（PulseMCP）至 50,000+（Glama），但大多数无人维护，厂商官方维护的仅数百个。MCP 已捐赠 Linux Foundation（2025-12-09）。
  来源：https://openhelm.ai/blog/mcp-registry-directory-guide （2026-07-09）、https://juejin.cn/post/7647785782203760680
- **企业治理模式已成型——MCP Gateway 是标准答案。** 市场分两层：开源（Bifrost、ToolHive、agentgateway）与企业平台（TrueFoundry、Composio、Lunar MCPX）。核心能力趋同：SSO/OAuth 2.1 + OBO 身份传递、action 级 RBAC、"Agent X 只能用只读工具"策略、审计日志、集中凭证管理、批准 server 白名单。
  来源：https://www.requesty.ai/blog/mcp-gateway-comparison-2026-enterprise-scalability-security、https://composio.dev/content/mcp-gateway-governance （均 2026-06）
- **协议内建工具分级词汇：** `ToolAnnotations`（`readOnlyHint`/`destructiveHint`/`idempotentHint`/`openWorldHint`）是 spec 正式字段，ChatGPT 插件提交强制要求；但**只是提示性 hint，不构成强制安全边界**，且大量现存 server 未标注（多个 GitHub issue 为证）。
  来源：https://sunpeak.ai/blogs/testing-mcp-tool-annotations/ （2026-07-22）、github.com/NetApp/harvest#4248 等
- **风险框架成熟：** OWASP MCP Top 10（2025 中发布）涵盖 tool poisoning、工具输出注入、供应链、无沙箱执行、rug-pull 更新等；真实事件：postmark-mcp npm 包 BCC 窃密（2025-09，首个野外恶意 MCP server）、GitHub MCP 间接注入泄露私有仓库（2025-05）。
  来源：https://glasp.co/articles/mcp-security-tool-poisoning-supply-chain、https://checkmarx.com/learn/mcp-security-risks-real-world-incidents-and-security-controls/

  来源：https://lobehub.com/mcp/ruan11223344-zentao-mcp （2026-07）、https://my.oschina.net/CeeYang/blog/19716250 （2026-07-07）

## ④ 对 SpecGuard 的可复用性判断（推断，基于上述事实）

| 维度 | 判断 | 说明 |
|---|---|---|
| Skill 格式兼容 | **低成本可复用** | 规范=「frontmatter+md+资源文件」，与自家 skill_loader 同构。对齐工作≈强制 name/description 校验、忽略未知字段、采用渐进披露（先加载 description 再加载正文）、规范目录名=name |
| 外部 skill 导入 | **需适配层** | 生态无签名/pinning 协议，须自建审查管线：静态扫描（注入模式、`<>`、可执行脚本）+ 沙箱试跑 + 人工 review + 白名单。参考：skillcheck（质量门）、openagentskill（审计评分）、CIS《第三方 MCP server 安全指南》思路平移 |
| 第三方 MCP server 接入 | **需适配层（重）** | SpecGuard 目前是单 stdio server 的 server 侧；接外部 server 需要 MCP **client** 能力 + 迷你 gateway（工具白名单、readOnly 强制、参数审计）。可直接用 ToolAnnotations 做初筛，但不能信任，须自行强制 |
| 禅道集成 | **部分可复用** | 可 fork ruan11223344/zentao-mcp 加速（Python、MIT 类个人项目），但须全面审计+补测试，不可直接上生产；若哪天迁 Jira 则直接接官方 server |
| MCP gateway 成品 | **暂不必引入** | 24 工具单 server 规模远未到 N×M 问题；但应吸收其设计词汇（只读/写分级、OBO、审计）预留在自有 server 内 |

## ⑤ 风险提示清单

1. **Skill 注入面**：36% 公开 skill 含注入；skill 可捆绑可执行脚本；frontmatter `<>` 可注入系统提示 → 导入即代码审查。
2. **供应链无信任根**：skills 规范无版本/签名/pinning；MCP 生态 rug-pull（postmark-mcp 先例）→ 版本锁定 + 源码快照 + 禁止自动热更外部 skill/server。
3. **Tool poisoning**：恶意 server 可通过工具描述劫持工具选择、通过返回值做间接注入和记忆投毒 → 外部 server 输出视为不可信数据，隔离高权限工具。
4. **Annotations 不可信**：readOnlyHint 是声明不是执行 → SpecGuard 须在自己的 client/gateway 层强制只读策略，而非依赖 server 自述。
5. **误报疲劳**：skill 扫描器 warn 误报率 ~42% → 审查管线需人工复核层，别全自动阻断。
6. **禅道 server 质量未知**：Unvalidated 个人项目，凭证走 .env 明文 → 审计、补 annotations、凭证走密钥管理后方可考虑。
7. **标准仍在变动**：skill `version` 字段、供应链信任指导均在提案阶段 → 适配层要做字段宽容（忽略未知 key），避免锁定草案行为。
