# SpecGuard Vision · 研发顺序与里程碑验收标准

> 目标：每个阶段效果最大化——依赖先行、价值拐点前置、独立支路并行、闸门先于 Agent、每阶段产出可演示闭环
> 基线：13 份模块设计（M01-M13）+ P1-P3 基座 + 架构快照 §8 测试入口
> 当前位置：agent 会话编排单元测试打磨中 → 下一步执行编排后的单元测试

---

## 1. 排序逻辑（六条原则）

1. **地基先行**：purpose 会话模型（M01/M12）是所有会话能力的公共地基——你当前的会话编排单测正是这一层，先做理所当然。
2. **价值拐点前置**：F1 面试最小闭环是路线图钦定价值拐点——只做它，产品经理就能在 AgentChat 里完成结构化面试，尽早拿出可演示成果。
3. **闸门先于 Agent**：确定性校验器（P0 清零、三闸、数据校验器）先落地，Agent 能力（数据制造、归因、材料解析）后上——否则 Agent 产出无闸可过，质量叙事崩塌。
4. **独立支路并行**：G1 图谱索引（M11）只依赖现有 anchors/covers/DAG，不依赖 specflow——Stage 3 起可与主线并行，不占关键路径。
5. **测试侧吃存量**：引擎/DAG/报告已在生产，M07-M09 是增强不是从零——排在 specflow 主闭环之后，用真实使用反馈校准需求。
6. **治理件随用随建**：Skill/MCP 治理（M13）拆成骨架（随 F3）→ 治理件（G2）→ 储备（P3 触发制），不提前平台化。

---

## 2. 总览：研发顺序（关键路径 → 并行支路）

```
你在哪 → [S0 会话编排单测] → S1 purpose 地基 → S2 F1 面试闭环 ★价值拐点
        → S3 材料包与 info_pack（‖ P-A 图谱索引并行启动）
        → S4 扫描仪与评分卡 → S5 三闸冻结 + 禅道集成
        → S6 测试侧三增强（缺口/数据制造/归因）
        → S7 血缘链 + 影响面图谱（汇合 P-A）
        → S8 Skill/MCP 治理件 + 对外 L0 开放面
P-A（并行支路，S3 起）：M11 图谱索引 + 覆盖缺口视图 → 快照机制
```

每阶段均含**回归门禁**（不过不得进入下阶段）：引擎改动必跑 `pytest -k engine_modes` + `pytest test_engine`；specstd 改动必跑 `pytest test_specstd`；入库前 `release_check.py` 三项门禁全 PASS。

## 3. 阶段明细与里程碑验收标准

### S0 · Agent 会话编排单元测试（当前阶段，收口）

> 范围：`agent/runtime.py` 工具分发 + 会话循环、`session.py` 工号隔离、`compactor.py` 压缩、`llm_client.py` 热加载——即 S1 地基的测试先行层。

**里程碑验收**
- [ ] 编排后的单元测试套件全绿（`pytest agent/`，无 skip 豁免项）
- [ ] 覆盖关键用例：会话创建/恢复、按工号 `sessions/{emp}/` 隔离、tool 分发路由、压缩触发阈值、配置 DB 热加载生效
- [ ] 含 `--mock` 模式可离线复跑（CI 可挂）
- [ ] 失败用例输出可定位到具体工具/轮次（不是泛泛 assert）

### S1 · purpose 会话地基（M01 + M12 骨架 + M13 P1 骨架）

> 把 S0 测绿的编排层升级为 purpose 终态：会话创建期锁定、提示词装配、工具白名单三层交集。

**里程碑验收**
- [ ] 会话模型 `purpose` 字段持久化且创建后不可变（写测试：改 purpose 请求被拒绝）
- [ ] `resolve_tools(session) = TOOL_REGISTRY ∩ profile.tools ∩ rbac_visible_tools` 运行时强制——越权调用确定性拒绝并留 WARNING 审计
- [ ] `agent/purposes/` 片段热加载（30s 内可见，不重启、不改 runtime）
- [ ] RBAC 过滤可用用途清单；会话归属发起人留痕
- [ ] 回归：S0 单测套件 + `python -m agent.cli --mock` 冒烟全绿

### S2 · F1 面试最小闭环 ★价值拐点（M02 + M04 台账 schema/P0 清零）

> 第一个可给领导演示的端到端：开标 → 分级提问 → 决策落台账 → P0 清零 → 归档。

**里程碑验收**
- [ ] 产品在 AgentChat 完成一轮 IV-xxx 面试全流程（复刻原型 S4 演示路径：Q1(P0)→Q2(P0)→D 落锤→Q3(P1)→归档）
- [ ] D-xxx 台账：P0/P1/P2 分级 + 落锤不可推翻仅可增补（amendment 链）+ 拍板类写操作不暴露给 MCP（通道级验证）
- [ ] P0 清零门禁为确定性校验（gate.py 纯函数）：未清零时冻结请求被硬拒
- [ ] 面试归档落 `.specflow/` 目录约定，可被审计回放
- [ ] 演示验收：对照原型 S4 对话流逐节点可演示

### S3 · 材料包与信息包（M03 + info_pack 补票）‖ P-A 并行启动

> 信息包成为面试燃料管线；同时**并行启动 P-A：M11 图谱索引 + 覆盖缺口视图**（不依赖 specflow，独立验收见 S7 汇合）。

**里程碑验收**
- [ ] `.md/.docx/.pdf` 三类材料上传→解析→议题候选（候选态 confirmed=0 不进上下文）
- [ ] 人拍板入包/入台账闸门生效；六分区 info_pack.yaml 装配器产出可被面试会话消费
- [ ] `info_pack.py` 挂载 TOOL_MODULES 补票完成，`list_tools` 计数与实际挂载一致（回归测试）
- [ ] 覆盖率机打依据（coverage_map）供 M04 五维评分消费（接口联调通过）

### S4 · F2 扫描仪与评分卡（M05 草案扫描 + M04 五维）

**里程碑验收**
- [ ] 草案 11 章齐全性 / SHALL / AC 可执行性机打校验（调 specstd conformance，纯读无副作用）
- [ ] 五维评分卡：机打维度走确定性校验器，LLM 预打分必须 QA 确认才生效（未确认=不生效测试）
- [ ] 68/70 未及格场景可复现：边界异常维度缺场景 → 阻断冻结并给出补充建议
- [ ] 触及 specstd 规则扩展走 Ask First 评审（流程记录）

### S5 · F3 三闸冻结 + 禅道集成（M05 + M06）

> specflow 主闭环收官：产物规格化、闸门化、跨系统挂链。

**里程碑验收**
- [ ] 需求侧三闸全链路：① 产品确认 ② specstd 合规 ③ P0 清零——任一未过冻结硬拒
- [ ] delta 三段式 + manifest 一致 + verify-delta V1-V6 机械校验全 PASS
- [ ] zentao-cli 建禅道故事：幂等键防重复建单、凭据仅环境变量注入、回滚不删禅道资产
- [ ] 故事点评估 skill：estimate 恒 suggested，产品确认才回写；编号登记 `sf_external_refs`
- [ ] 提 BUG 双入口可用；入口① 仅 FAIL + 人为疑似缺陷定性可提单（SKIP/BLOCKED 提单被拒）
- [ ] 计划只能由 delta 导入生成：手动新建计划无 API（铁律 6 负向测试）

### S6 · 测试侧三增强（M07 + M08 + M09）

> 闸门已齐，Agent 后上——数据制造与归因 Agent 在闸门保护下启用。

**里程碑验收**
- [ ] 覆盖缺口三态泳道与真实基线一致（盘点活动管理 13 FR 案例可复现）；草稿不计覆盖
- [ ] 草稿三闸状态机（sg_draft_gates）落到 promote 硬前置；「生成下一批」只产草稿不产计划
- [ ] 测试数据制造 Agent：产物一律草稿态过三闸；数据校验器（实例完整性/调度合法性/版本可仲裁）硬拒不合格实例；只消费 `systems/{system}/` 适配包资产，引擎零改动（`pytest test_engine` 无改动验证）
- [ ] 失败归因 Agent：suggestion 永不自动转 decided（decided_by/decided_at 留痕）；环境问题定性强制附诚实性复核；SPQ 自动装配进下轮面试信息包闭环

### S7 · 血缘链 + 图谱全景（M10 + M11，汇合 P-A 支路）

> P-A 支路（图谱索引，S3 起并行）在此汇合验收；血缘链做图谱的线性投影。

**里程碑验收**
- [ ] graph_index 由 anchors/covers/DAG/manifest/台账确定性派生；指纹失效即重建；删除重建后同一张图（可删可重建验证）
- [ ] 图谱绝不回写 spec（写路径不存在验证）
- [ ] L0/L1/L2 语义缩放 + 三镜头可用；里程碑快照三触发点（冻结/归档/执行完成）+ 演化 diff（ADDED/MODIFIED/REMOVED 可凭指纹重建校验）
- [ ] 血缘链 Q1/Q2 trace：从场景向上到面试决策、从 FR 向下到执行报告，全链不断；断链=WARNING（BL 规则集生效）
- [ ] 外部锚点（ZT-STORY/ZT-BUG）虚线节点只登记不拥有；SPQ→面试信息包 loop-back 可视

### S8 · Skill/MCP 治理件 + 对外 L0 开放面（M13 P2 + M12 收尾）

**里程碑验收**
- [ ] skill 格式对齐开放规范（name/description 强校验、目录名=name、未知字段宽容、渐进披露）；注册表 `/api/agent/skills` 可查，悬空引用加载期报错

- [ ] 面试三口径落实验证：过程类工具在 open/ 不存在；产物五件套可读；议题提交落草稿待人开标
- [ ] P3（审查管线完整化/对外 L1/生态 Registry）不排期，仅文档挂触发条件

## 4. 效果最大化的三个关键打法

1. **S2 之后即可汇报**：F1 闭环 + 原型 S4 演示面 = 第一个领导可见成果；此后每个阶段都有对应的演示叙事（S5→禅道、S6→测试工作台、S7→血缘图谱、S8→编码 Agent 旗舰场景），原型屏与研发阶段一一对应。
2. **P-A 支路白捡并行产能**：M11 图谱索引不依赖 specflow（S3 即可启动），若主线人力紧张可暂缓、若有余力则 S7 提前汇合——两种走法都不阻塞关键路径。
3. **测试资产复利**：S0 的编排单测套件是后续每阶段回归门禁的底座；每阶段新增闸门都配负向测试（越权拒绝/未清零拒绝/草稿逃逸拒绝），这些负向测试本身就是「确定性治理」的演示证据。

## 5. 红线（全程有效）

- **engine/ 冻结层零改动**：任何阶段发现需要改引擎才能交付，停下来评审——适配永远走 `systems/{system}/` 子包与工具注册。
- **specstd 规则扩展 = Ask First**。
- **绕闸生效 = 阻断性缺陷**（M12 验收红线，全阶段适用）。
- DB 新表一律 `sf_*`/`sg_*` 前缀，不动现有表；workbench.db 不入库。
