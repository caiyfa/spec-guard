# 登录首页（导航枢纽型 · 免菜单权限）设计

> 2026-08-18 · 需求：给 SpecGuard 设计登录后展示的首页（http://127.0.0.1:9100/），无需菜单权限。
> 布局方案经可视化 mockup 三选一定稿：方案 A（Hero + 分组卡片网格）。
> 可视化过程稿存于 `.superpowers/brainstorm/home/content/`（不入 git）。

## 一、现状与根因（已实测确认）

| 现象 | 根因 |
|---|---|
| 所有用户（含 admin）登录后落地 🔒「无权限访问该页面」 | 提交 6b33c78 把 `/` 指向 AgentChat 并注释「登录即用无需授权」，但前端路由守卫 `App.tsx` 只认 `menus/me` 菜单树里的 path，没有任何菜单的 path 是 `/`，于是 `noAccess=true` 全员被拦 |
| 🔒 页「返回仪表盘」链接是死循环 | 该链接 `to="/"`，同样被守卫拦截 |
| 工作区选择器显示「无可用工作区」 | `/api/workspace/list` 绑定 menu-workspace，零权限用户 403（符合预期，非本设计范围） |

免权数据通道（MenuGuard 白名单 + 公开菜单）：`auth/me`（身份）、`/api/menus/me`（可见菜单树）、`/api/agent/*`（menu-agent 公开）。

## 二、设计决策（用户已逐项确认）

- **D1 内容定位 = 导航枢纽型**：欢迎区 + 按当前用户可见菜单动态渲染的功能入口卡片 + Agent 对话主入口。数据只依赖免权通道（`auth/me` + `menus/me`），**后端零改动**。
- **D2 布局 = 方案 A（Hero + 分组卡片网格）**：顶部 Hero（时段问候 + 姓名 + 角色徽章 + 平台简介 + 主 CTA），下方按菜单分组平铺入口卡片，响应式 1/2/3/4 列。
- **D3 零权限兜底 = 正常渲染 + 提示条**：页面结构不特殊化；当可见菜单仅含公开菜单（对话）时，Hero 下方出现提示条「当前账号暂未开通功能菜单，可先在 Agent 对话中体验；更多功能请联系管理员在『菜单管理 → 角色授权』中开通」。
- **D4 页面去向 = 首页独占 `/`**：`/` 让给新首页；AgentChat 只在 `/agent`（菜单「对话」不变）；Dashboard 保持 `/dashboard`；侧边栏菜单区顶部加静态「🏠 首页」项（前端硬编码，不进后端菜单树、不参与授权）；Logo 区点击 → `/`。
- **D5 兼容背景修改（K-044，用户特别强调）**：首页不得涂刷任何页面级不透明背景——内容区不挂 `bg-surface-*` 满铺类，让 `html[data-bg='1']` 的三层模型（body::before 图片层 → body::after 主题罩层 → #root 内容层）自然透出；Hero 氛围光晕只用半透明 radial-gradient（可叠加在罩层上）；卡片/提示条沿用 `surface/border` token（frost 等主题下半透明玻璃态自动生效）。若需页面级底色，必须按 Login 页模式 `useBg().image ? '' : 'bg-surface-1'` 条件挂载。

## 三、信息架构（新页面 `workbench/frontend/src/pages/Home.tsx`）

```
┌ Hero ────────────────────────────────────────────┐
│ 👋 {时段问候}，{user.name}  [角色徽章(+N)]        │
│ 契约驱动的场景测试与 AI 智能编排平台              │
│ [💬 开始 Agent 对话] → /agent                     │
└──────────────────────────────────────────────────┘
┌ 提示条（仅可见菜单 ≤ 公开菜单时）───────────────┐
│ ℹ️ 暂未开通功能菜单 … 联系管理员开通             │
└──────────────────────────────────────────────────┘
┌ 功能入口卡区（menus/me 分组 → 响应式网格）──────┐
│ ┌卡┐ ┌卡┐ ┌卡┐ ┌卡┐                            │
│ 卡头 = 分组 icon + 分组名                       │
│ 卡体 = 组内菜单项链接列表（逐项 <NavLink> 跳转）│
└──────────────────────────────────────────────────┘
```

- 时段问候：本地时间 5–11 早上好 / 11–14 中午好 / 14–18 下午好 / 18–23 晚上好 / 23–5 深夜好。
- 角色徽章复用顶栏配色（admin 紫 / tester 蓝 / product 琥珀 / viewer 灰），多角色 `+N`。
- 卡片数据即权限：`navTree` 由 `AppContent` 拉取后经 props 传入（**不重复请求** `menus/me`）；空分组不渲染（与后端 `menus_for_user` 行为一致，双保险）。
- 视觉沿用工作台 token：`card-hover`、`brand-gradient`、`surface-2/3`、`border`、`info`；亮暗五主题自适应。

## 四、前端改动点

| 文件 | 改动 |
|---|---|
| `pages/Home.tsx` | 新增。props：`{ user: CurrentUser; navTree: NavGroup[]; navLoaded: boolean; navError: boolean; onRetryNav: () => void }` |
| `App.tsx` | ① 路由 `/` → `<Home …/>`（AgentChat 仅从 `/agent` 可达）；② 守卫新增前端常量 `PUBLIC_PATHS = ['/']` 直接放行（修复全员 🔒 线上 bug）；③ `noPadding` 移除 `/`；④ 侧边栏菜单区顶部加静态「🏠 首页」NavLink；⑤ Logo 区包 `<NavLink to="/">`；⑥ 🔒 页死链文案「返回仪表盘」→「返回首页」（仍指向 `/`，修复后可达）；⑦ `menusApi.me()` 拉取失败时记录 `navError` 供 Home 渲染重试 |
| 后端 | **零改动**（`auth/me`、`menus/me` 本就在 MenuGuard 白名单） |

## 五、边界与错误处理

- `menus/me` 失败 → Hero 照常渲染（`auth/me` 已有身份），卡片区显示「菜单加载失败」+ 重试按钮（触发 `onRetryNav` 重新拉取）。
- `navTree` 仅含公开菜单 → 提示条出现（D3）。判定方式：前端常量 `PUBLIC_MENU_PATHS = ['/agent']`（与后端 `PUBLIC_MENUS` 对齐），`navTree` 全部 item.to 都属于该集合时提示条出现。
- 菜单项点击跳转目标仍受既有路由守卫保护——首页只是导航，不放松任何页面权限。
- 自定义背景图（K-044）开启时：页面无满铺不透明背景，Hero 光晕为半透明叠加层，卡片保持 surface token 可读性（D5）。
