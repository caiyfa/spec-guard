# DB 证据面板与辅助会话机制设计（含 SQL 助手首用途）

> 日期：2026-08-25 | 状态：已评审待实施 | 上游讨论：会话 `20260825_151821_3178914e`（历史盘点用例生成）

## 1. 背景与动机

会话 `20260825_151821_3178914e`（工作区「人才发展」，历史盘点模块测试用例生成）暴露出 DB 验证是测试用例生成的高频刚需：

- 规划的 7 个场景中至少 4 个直接依赖 DB 查询（数据落地断言、等效 SQL 计数、db_query 校对、given 前提确认）；
- 权限过滤类场景的通用断言模式「total = 等效 SQL 无权限片段计数」要求**每写一个场景先跑一次等效 SQL**——这是测试人员日常动作，非低频操作；
- 现有 4 条 DB 能力（db_evidence 工具 / db_query 场景步骤 / oracle 断言器 / ReadOnlyDb 客户端）没有一条面向「用户直接执行」；用户被迫跳出工作台开 Navicat/Archery——脱离场景上下文且有误写风险。

同时，SQL 的编写本身需要解释表字段关系、说明设计理由、多轮迭代试跑——这类冗长过程若发生在主会话会持续烧主会话上下文窗口，污染「测试设计」主线语境。由此产生第二层需求：**从主会话派生辅助会话，专职 SQL 生成，产出物回流主会话**。

## 2. 目标与非目标

### 目标

| # | 目标 | 决策来源 |
|---|------|---------|
| G1 | DB 证据面板：登录用户可直接执行只读 SQL（Monaco 编辑器 + schema 切换 + 结果表格 + 查询历史） | 拍板「低成本高收益组合①」 |
| G2 | 上下文联动入口：场景编辑器 db_query 步骤「试跑此 SQL」、执行报告失败断言「查 DB 证据」 | 拍板「组合②」 |
| G3 | AgentChat 中 db_evidence 结果表格化渲染 | 拍板「组合③」 |
| G4 | 辅助会话通用机制：父会话链接 + 每轮快照注入 + 产出物引用回流，代码零用途特化 | 拍板「通用机制+SQL首用途」 |
| G5 | SQL 助手首用途：右侧面板页签形态的迷你对话，解释表关系/设计理由/多轮迭代 | 拍板「右侧面板页签」 |

### 非目标（防蔓延红线）

- **不做写操作**：只读守卫语义（SELECT/SHOW/DESCRIBE/EXPLAIN、拒危险子句、拒多语句）原样继承，永不做 INSERT/UPDATE/DDL；
- **不做数据库管理**：表结构管理、索引优化、导出管道一律不进；
- **不设 RBAC 门槛**：用户明确拍板无权限限制（审计仍保留，见 §9）；
- **不做轮内实时同步**：主会话变更对执行中辅助会话的可见性以轮为粒度，不做同轮推送；
- **不做多辅助会话并发**：同一父会话 + 同 purpose 幂等一对一（首期）。

## 4. Part A：DB 证据面板

### A1. 后端：连接装配下沉 sg_core（三端共享）

现状：`mcp_server/tools/attribution.py::_handle_db_evidence` 内联装配连接（每次调用新建连接、无缓存）。面板高频使用需要连接复用，且三端（db_evidence / DB 面板 / 场景试跑）应走同一条守卫链。

**新增 `sg_core/db_access.py`**（依赖方向 sg_core→engine，合法）：

```python
# 进程级连接缓存：键 = (workspace, system, env, schema_name)
# ReadOnlyDb._ensure_alive 已有 ping 重连，缓存实例可长期复用
def get_db_connections(env_name: str = "") -> tuple[dict[str, ReadOnlyDb], str]
def invalidate_cache() -> None          # 工作区/环境切换时失效
def execute_readonly(sql: str, schema: str = "", max_rows: int = 1000,
                     vars: dict | None = None) -> dict
    # 返回 {rows, row_count, truncated, columns, elapsed_ms, sql_rendered?}
```

- `execute_readonly` 内部：变量插值（`engine/interpolation.render`，vars 缺键时诚实报「变量 X 未定义」）→ ReadOnlyDb 守卫（SQL 词法黑名单语义零变更）→ 执行 → 读 `last_truncated` 标志外抛；
- 缓存失效钩子：specstd workspace contextvar 切换时（`set_context_workspace` 侧不侵入，由 db_access 在每次取连接时比对当前 workspace 键，键变化即重建）；
- **db_evidence 改造**：`_handle_db_evidence` 删除内联装配，改调 `sg_core.db_access.execute_readonly`，返回结构不变（含 rows 前 100 行）；守卫拒绝文案不变（存量测试 `test_acceptance_fixes.py` 必须零修改通过）。

### A2. 后端：DB 面板 router

**新增 `workbench/backend/routers/db_console.py`**，`main.py` include_router：

| 端点 | 语义 |
|------|------|
| `GET /api/db/schemas` | 列当前工作区 env 配置的 schema 清单（名称 + 是否 default + 连接健康态探活 SELECT 1） |
| `POST /api/db/query` | body `{sql, schema?, vars?}` → `execute_readonly` → 结果 JSON；**每次调用记审计**（§9） |

- 无 RBAC 门槛（登录即可用）；工作区上下文沿用全局工作区中间件（X-SG-Workspace header）；
- 守卫错误原样透传（400 + SqlGuardError 文案），前端就地显示；
- 审计失败不阻断查询（与 T-082 同纪律）。

### A3. 前端：DB 证据面板页面

**新增 `pages/DbConsole.tsx`** + 路由 `/db-console`（App.tsx）+ 菜单项（菜单守卫不设门槛）：

- **编辑器**：Monaco SQL 模式（复用现有 Monaco 集成方式），Ctrl+Enter 执行；
- **schema 切换器**：下拉列出 `GET /db/schemas` 结果，默认 default；不可达 schema 置灰标注「连接失败」；
- **结果区**：`SqlResultTable`（见 A5）+ 行数 + 截断提示「结果超 1000 行已截断」+ 耗时；
- **三态分离**（前端体验基线③）：加载中 / 空态（无查询历史时引导文案）/ 错误（守卫拒绝与连接失败分色）；
- **查询历史**：localStorage 存最近 50 条 `{sql, schema, ts}`，点击回填编辑器；跨设备不同步（刻意为之，SQL 非敏感但无需落库）；
- **状态持久化**（基线①）：schema 选择、编辑器草稿存 localStorage，进入即恢复；
- 页面顶部明示：**「只读查询（共享只读账号，无行级权限）」**——用户须知。

### A4. 上下文联动入口

**入口①（场景编辑器试跑）**：`StepFormCard.tsx` 的 `db_query` 步骤编辑区（L319 区块）加「▶ 试跑」按钮：

- 点击 → 取当前编辑中的 sql 模板 → 前端收集已知变量（无运行时变量，编辑态 vars 恒空，env.* 由后端插值）→ `POST /api/db/query {sql, schema: 步骤声明的 schema, vars: {}}`；
- 插值失败（引用了 `{{上游save变量}}`）→ 诚实提示「编辑态试跑不含运行时变量 X，请先执行场景或手工替换」；
- 结果以弹层 `SqlResultTable` 展示（与页面同组件）。

**入口②（报告失败断言查证）**：`History.tsx` 报告详情的失败 case 区块，若 case 含 db_query 步骤或 db 类断言差异，在断言差异旁加「🗄 查 DB 证据」按钮：

- 点击 → 取 case 里的 sql 模板（cases/*.json 的 steps[].sql）→ 跳转 `/db-console?sql=<urlencoded>`；
- DbConsole 挂载时解析 query param 回填编辑器并自动执行一次。

### A5. 前端：SqlResultTable 组件（三处复用）

**新增 `components/SqlResultTable.tsx`**：轻量表格（列头取 dict 首行键序，行数 ≤1000，横向滚动，单元格超长省略 + hover 展开）；输入统一为 `{rows: list[dict], truncated: bool, row_count: int}` 形态。三处复用：AgentChat 工具块（G3）、DB 面板结果区（A3）、SqlAuxPanel 试跑结果（C2）。

**G3（AgentChat 表格化）**：`agentChat` 工具块渲染处（ToolGroupBlock/工具结果展示链）识别 attribution 工具 db_evidence 输出——判定条件：工具名 `attribution` 且结果 JSON 可解析且含 `rows` 数组 → 以 SqlResultTable 替代纯文本渲染（折叠态显示「SQL 查询结果 N 行」，展开表格）；解析失败回退纯文本（零风险降级）。

## 5. Part B：辅助会话通用机制

### B1. 术语与机制定位

- **主会话（parent）**：用户在 AgentChat 正常创建的会话；
- **辅助会话（aux）**：从主会话派生、`kind: "aux"` 标记、专职某 purpose 的会话。本质 = **普通会话 + 父链接 + 每轮快照注入 + 会话树隐藏**——runtime 零改动，全部机制在 session 模型与 WS 层。

隔离铁律（设计不变量）：辅助会话对主会话的影响只有一条通道——用户显式点「引用」；主会话对辅助会话的影响只有一条通道——每轮快照注入。两条通道外，两个 JSONL 文件物理无关。

### B2. 会话模型扩展

`agent/session.py`：

- `create(..., extra_meta: dict | None = None)`——透传写入首行 meta 与 `_meta.json`（现有签名只收 purpose，不动既有调用方）；
- 辅助会话创建时写 `kind: "aux"`、`parent_session_id`；
- `save()` 的 meta 继承清单（L154 `for k in (...)`）追加 `"kind", "parent_session_id", "last_parent_fp"`（末项见 B4 快照指纹）；
- `list_sessions()` 返回值追加这两个字段（前端据此过滤）。

### B3. 派生 API（spawn）

`workbench/backend/routers/agent.py` 新增：

```
POST /api/agent/sessions/spawn  {parent_session_id, purpose}
→ {session_id, created: bool}
```

- 校验：父会话存在、属当前用户、purpose 合法（load_purpose 通过且角色∩purpose.roles 非空——与现有建会话校验同款）；
- **幂等**：同父会话 + 同 purpose 存在未归档 aux 会话 → 直接返回该会话（`created: false`）；已归档 → 新建；
- 不校验父会话 purpose（机制通用：任何 purpose 的会话都可派生辅助会话）。

### B4. 每轮快照注入（主→辅单向）

**落点：WS 层**（`agent.py` 构造 `ws_message` 处，与 `_process_references` 的 `ref_block` 完全同模式、同代码位置）：

- 会话 meta 含 `parent_session_id` 时，每轮发消息前调 `_parent_snapshot(parent_sid)` 生成 `<parent_context>` 块前缀拼到 `ws_message`；
- 快照内容（合计截断 8KB）：
  - 父会话当前 scenario_id 与信息包文件清单（读父会话 meta + `_build_scenario_context` 同源数据）；
  - 最新草稿文件名 + sha（父会话 message 链中 doc_write/write_draft 足迹的最新态）；
  - 最近 1 条 assistant 消息摘要（前 500 字符）；
  - 变更标记：与上一轮注入的快照指纹（sha256-12）对比，**无变化时只注入一行「主会话自上轮起无变更」**（省 token）。
- 指纹存辅助会话 meta（`last_parent_fp`，save 继承清单同 B2 追加，B2 已含）；
- 父会话不可读（删除/跨用户）→ 注入「父会话不可读」降级行，会话继续不炸；
- 前端 groupMessages 跳过该 system 前缀块（与 skill_hint 同通道语义：LLM 可见、前端不显示）。

> 已知边界：主会话在辅助会话**执行中**的变更，要等辅助会话下一轮才可见（同轮实时推送不做——复杂度不成比例）。

### B5. 会话树过滤

`list_sessions` API 返回带 `kind` 字段；前端 `SessionTree.tsx` 过滤 `kind === 'aux'` 不显示。辅助会话只活在面板页签里，其生命周期跟随面板（页签记住 aux session_id，localStorage 持久化——基线①）。

### B6. 产出物回流（辅→主，用户中介）

**机制 = Agent 落盘 + 前端 @draft 引用**（零新后端）：

1. 辅助会话提示词要求：SQL 定稿后调 `write_draft` 落盘 `{语义名}.sql`（write_draft 现有路径守卫天然支持非 YAML 文件名；.sql 草稿**不可能通过三闸入库**——promote_draft 有 YAML 格式校验，天然不会污染场景库）；
2. 面板「产出物区」列出该辅助会话 write_draft 落盘的文件（复用 sessionDrafts 跟踪机制——session_context 反挂链路现成）；
3. 每个产出物两个按钮：
   - **「📎 引用到主会话」**：纯前端——把 `@draft:{文件名}` 预填主会话输入框（复用 ChatInput 的引用插入通道），发送时走现有 references 注入（20KB 上限对 SQL 绰绰有余）；
   - **「▶ 在 DB 面板打开」**：跳 `/db-console?sql=...`（A4 同款参数）。

> drafts 页（Drafts.tsx）会显示 .sql 文件——可接受：产出物可见性反而是特性（有 doc_write 足迹 + 审计）。

## 6. Part C：SQL 助手（首用途）

### C1. 用途定义

**新增 `agent/purposes/sql_assistant.md`**：

```yaml
id: sql_assistant
title: SQL 助手
icon: 🧮
chips: [表关系解释, SQL 迭代, 只读试跑]
roles: [admin, tester, viewer, product]   # 全角色（用户拍板无 RBAC 限制）
domains: [run, spec, scenario]            # run=db_evidence 试跑；spec=表结构文档/FR；scenario=读场景草稿
tools: []
panels: []
```

提示词要点（正文）：

- **解释义务**：每条产出 SQL 附「用到的表 + 关联键 + 过滤条件逐条说明」；
- **设计理由**：为什么这么写（业务语义 → SQL 片段的映射）；
- **守卫内化**：只生成 SELECT/SHOW/DESCRIBE/EXPLAIN，不生成 FOR UPDATE / INTO OUTFILE 等被拒写法；
- **插值语法**：支持 `{{var}}` / `{{env.*}}`（对齐场景 db_query 语法），并解释变量来源；
- **定稿落盘**：`write_draft` 写 `{场景ID或语义名}.sql`；
- **边界认知**：「你的产出由用户决定何时引用回主会话，不要假设主会话已看到；每轮消息前的 `<parent_context>` 是主会话最新快照」。

### C2. 前端：SQL 助手页签

- `SidePanel.tsx` 的 SIDE_TABS 追加 `{ id: 'sql_aux', label: '🧮 SQL 助手', scope: 'purpose' }`；
- `test_workbench.md` 的 panels 追加 `sql_aux`（purpose 声明驱动，其余 purpose 不受影响）；
- **新增 `pages/agentChat/SqlAuxPanel.tsx`**（迷你对话）+ `useAuxSession` hook：
  - 页签首次激活：调 spawn API（幂等）拿 aux session_id → 开**第二条 WS 连接**（现有 `/api/agent/ws` 端点原样复用；K-015 并发防护按 session_id 隔离，与主连接不冲突）；
  - 迷你对话：复用现有消息渲染链的轻量组合（流式文本 + 工具块 + db_evidence 表格化同 G3），不带 SessionTree/标题栏；
  - 产出物区：B6 的两按钮；
  - 输入框与主会话独立；发送失败保留草稿（与 ChatInput 同纪律）；
  - 辅助会话执行中主会话仍可正常使用（两条 WS、两个 runtime、两份 metrics 互不阻塞）。

### C3. 与 DB 面板互跳

- DB 面板编辑器旁「🤖 交给 SQL 助手」按钮：当前 SQL 文本写入 `sessionStorage('sg_sql_aux_pending')` → 跳 `/agent` → AgentChat 挂载时检测 pending → 激活 sql_aux 页签并以该 SQL 作为首条消息自动发送；
- SqlAuxPanel 产出物区「▶ 在 DB 面板打开」（B6）——双向打通。

> **2026-08-26 修订（SQL 探索模式）**：上述「跳页互跳」升级为「会话内嵌」——SqlAuxPanel 产出物区「▶ DB 面板」不再 `window.open` 跳独立页，而是经 `SqlAuxBridgeCtx`（contexts.ts，GateDockCtx 同款注入模式）通知 AgentChat 进入 SQL 探索模式：主会话对话区 display:none 最小化（K-039 先例，WS/滚动状态不卸载，左侧留 💬 细条可恢复）、SidePanel（sql_aux 页签）撑宽 45% 居左、内嵌 DbPanel（agentChat/DbPanel.tsx，与独立页共享 useDbConsole hook，草稿/schema/历史 localStorage 互通）居右；initialSql 回填自动执行。内嵌 DbPanel 的「🤖 交给 SQL 助手」经 onHandToAux 直发左栏辅助会话（不经 sessionStorage 跳页中转）。/db-console 独立页保留（History.tsx 等入口）。

## 7. 隔离保证矩阵

| 约束 | 机制 | 违反可能性 |
|------|------|-----------|
| 辅助会话不能变更主会话上下文 | 物理：两个 JSONL，runtime 只写自己 session_id 的文件；逻辑：辅助会话工具面无「写其它会话」能力；唯一回流通道 = 用户显式点引用 | 零（除非改 runtime 本身） |
| 主会话变更，未结束的辅助会话知道最新 | 每轮 user message 前缀注入父会话快照（B4，有变化才注入） | 轮粒度可见（同轮不保证，已知边界） |
| 产出物回供主会话 | write_draft 落盘 + 用户点「引用」@draft 注入（B6） | 主会话 Agent 仅在用户发送带引用的消息时可见 |

## 8. 错误处理与边界

| 场景 | 行为 |
|------|------|
| 父会话删除/归档/跨用户 | 快照注入降级「父会话不可读」，辅助会话继续可用 |
| 父会话 purpose 与辅助不同 | 不校验（机制通用性）；快照只传事实不传提示词 |
| spawn 时 purpose 非法 | 400 错误文案列合法 purpose |
| DB 未配置（env yaml 无 db 段） | schemas 返回空清单 + 面板空态提示「环境配置未设置 db 段」；试跑/查询同款诚实报错 |
| 编辑态试跑引用运行时变量 | 插值失败提示具体变量名，不静默空值 |
| 辅助会话 token 计量 | 独立 metrics 文件（会话隔离体系现成），面板显示独立用量 |
| 第二条 WS 断连 | 复用现有重连逻辑（页签内局部状态），不影响主 WS |
| .sql 草稿与三闸 | promote_draft YAML 校验天然拒绝，不可能入库 |

## 9. 安全与审计

- **无 RBAC 门槛**（用户拍板），但 **DB 面板每次查询记审计**：`user_store.audit(emp_no, "db_query", schema, detail=SQL前500字符 + 行数)`——审计失败不阻断（T-082 纪律）；
- 只读守卫链单一事实源：`engine/db_oracle.py` 的 SqlGuardError 语义零变更，db_evidence/db_console/试跑三端共用；
- 共享只读账号无行级权限的事实在面板明示（A3）；
- 辅助会话工具调用照常走 T-081 副作用指纹 + T-082 审计（机制层零豁免）。
