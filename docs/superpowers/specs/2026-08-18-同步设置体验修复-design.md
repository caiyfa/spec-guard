# 同步设置体验修复（弹层秒开 + 去 ID 手填 + 链接解析）设计

> 2026-08-18 · sess-agentchat-material · §4.10 支线延伸（T-937）
> 背景：用户验收反馈——「弹出框弹出速慢；群聊列表/监听用户/按用户搜索文档的用户下拉都需通过飞书 CLI 加载选项，别指望用户手填 id 或 token；飞书云文档可以给链接，但文档 token 要自己去解析」。

## 一、根因与实测定案

| 现象 | 根因/实测 |
|---|---|
| 弹层弹出慢 | `openWatch` 中 `getWatch` → `listChats`（lark-cli 子进程 1~数秒）**串行等完才 `setOpen(true)`**，弹层被 CLI 阻塞 |
| 文档用户下拉非 CLI | `<select>` 数据源 = 已添加且勾了 docs scope 的监听用户，必须先加监听人才能搜文档，路径断裂 |
| token 手填 | 手填 textarea 要求用户从链接抠 token；wiki 链接的 node_token ≠ 文档 obj_token，用户无从解析 |
| wiki 解析命令 | `wiki +node-get --node-token <URL> --as user`：成功返回 `data.obj_token/title/owner/obj_type`；**非 wiki 的普通云文档 404**（code 131005 "document is not in wiki"）——docx 与 wiki 必须分流 |
| 进度行分流 | `Fetching wiki node...` 走 **stderr**、stdout 纯 JSON（实测）——`_run_lark` 的 `json.loads(stdout)` 兼容，解析层零改动 |

## 二、设计决策

- **D1 弹层秒开**：点击立即渲染弹层（骨架态）；`getWatch`（本地 yaml，快）与 `listChats`（CLI）**并行**异步填充；后端 `list_my_chats` 加 60s TTL 内存缓存（key=当前工号；失败结果不缓存，重试即时生效）。
- **D2 手填兜底完全删除**（用户确认）：群聊 chat_id textarea 删除，加载失败 → 错误提示 + 重试按钮；文档 token textarea 替换为「粘贴链接解析」输入（兼容裸 token 透传，天然兜底）。
- **D3 文档用户下拉改「搜索框 + 已配置快捷标签」**（用户确认）：输入关键词 → 复用 `searchUsers`（CLI）→ 选中任意用户即可检索其文档；已配置 docs scope 的监听用户以快捷标签列旁可点选。
- **D4 链接粘贴解析**：新端点 `GET /api/feishu-pool/resolve-doc?input=`：
  - `/docx/<tok>` URL 或裸 token → **本地解析**（路径末段，零 CLI 调用秒回；title 无，落池后材料池可读层自然有标题）
  - `/wiki/<tok>` URL → `wiki +node-get` → `{token: obj_token, title, url, doc_type: obj_type, owner_open_id, owner_name: ""}`（owner_name 需再查通讯录，本版省略）
  - `/minutes/` `/base/` 及其他链接 → 明确错误「监听文档仅支持云文档（docx/wiki）链接」
- **D5 回显统一**：打开弹层时 watch.docs 回填到**勾选列表**（带 title/url 显示），不再 textarea 裸 token 回显；watch.docs 项新增 `title` 字段（存储层白名单只过滤顶层键，docs 项内字段自由，零迁移）。
