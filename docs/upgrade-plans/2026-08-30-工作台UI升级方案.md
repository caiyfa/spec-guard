## 二、设计目标与原则

**目标**：不改任何功能与信息架构，把「描边徽章、玻璃感淡填、信息分层、紧凑但呼吸、主题自适应」
这套已在 🧭 路径图验证的设计语言推广为全站统一的视觉系统；五套主题下同等成立。

**五条原则**（评审逐条对照）：

1. **主题自适应优先于单点美观**——一切颜色必须走变量（或 8 位 hex 淡填等双主题可证技巧），
   任何「只在某个主题下好看」的样式视为缺陷。light/frost 是第一等公民。
2. **状态语义全站统一**——PASS/FAIL/SKIP/BLOCKED/WARN/INFO 的表达收敛为**一种徽章**（描边徽章），
   颜色只来自 6 个状态变量；状态不再依赖 emoji 宽度对齐。
3. **信息分层替代信息堆叠**——每处展示先分「主信息/证据/辅助」三层再排版（路径图两行徽章是样板），
   拥挤热点先减层再减字。
4. **收敛优于新增**——先合并既有 6 种徽章/4 种页签/3 种危险红为各 1 种，再谈新组件；
   消灭散点（字号/透明度/圆角给档次），不发明新风格。
5. **只改皮不改骨**——纯样式与组件封装层改造，不碰交互逻辑/状态管理/持久化键/路由；
   体验基线五条（持久化/细节不外露/三态分离/单点刷新/缺失配置就地补）只能加强不能倒退。

**图标策略（拍板项，本方案默认 A）**：
- **A（默认，零依赖）**：保持 emoji/Unicode 体系并规范化分工——emoji 只用于页签/菜单/页面标题
  （已是本站风格资产）；**状态表达一律退出 emoji**，改用图形徽章（描边徽章/圆点/spinner）。
- **B（备选，Ask First 项）**：引入 lucide-react（~30KB gzip，树摇）。若未来要走 B，只替换状态与
  按钮图标，页签 emoji 保留。新增依赖属 AGENTS.md「Ask First」，本方案不为其开路。

## 三、L0 设计 token 层（地基改造）

### 3.1 字号阶梯收敛（治 E2）

散点 8/9/10/11/12/13px → 5 档语义阶梯，tailwind extend 后全局替换：

| 档 | 值 | 语义 | 吸收现状 |
|----|-----|------|----------|
| `fs-micro` | 9px | 徽标计数、极辅助标注 | text-[8px]/[9px] |
| `fs-aux` | 10.5px | 辅助信息、证据行、表头 | text-[10px] |
| `fs-body` | 12px | 正文/列表/按钮主力 | text-[11px]/text-xs |
| `fs-lead` | 13px | 段落正文、强调读文 | text-sm/text-[13px] |
| `fs-title` | 15px | 页面标题/卡标题 | text-lg/text-base |

- 实施：`tailwind.config.js` extend fontSize 五档 → 全局机械替换（每档一个 codemod 式替换，
  替换量约 870 处但纯样式）→ **ratchet**：oxlint 自定义规则或 grep 闸禁止新增 `text-[Npx]`。
- 正文主力从 11px 抬到 12px 是刻意的「去粗糙」动作（当前 10-12px 偏小是密度失控的共谋）。

### 3.2 状态色透明度档次约定（治 E1/E3 的一半）

消灭「info 一族 15+ 种透明度、200+ 处」的随机性，固定三档（对齐 mermaid 升级实证值）：

| 档 | 透明度 | 用途 | 例 |
|----|--------|------|-----|
| fill/soft | 10% | 大面积底（选中行、软高亮） | `bg-info/10` |
| fill/badge | 16% | 徽章/描边卡填充（玻璃感） | `bg-pass/15`（就近归档） |
| stroke | 40% | 描边（徽章边、引用竖线） | `border-info/40` |

- 既有 `bg-info/20`×56、`/15`×33、`/90`×22 等就近归档；`/90` 类实填只保留给实心主按钮。
- 配套：原生 tailwind 直色 → 变量映射表（`text-red-400`→`text-fail`、`bg-red-900/40`→`bg-fail/15 text-fail`、
  `bg-amber-900/30 text-amber-300`→`bg-warn/15 text-warn`、`text-green-400`→`text-pass`…）；
  内联 hex ×47 逐处归变量（DagEditor/ScenarioNode/ChatMessageView 的 SENDER_PALETTE 移入 themes.css 或 JS_THEME_TOKENS）；
  `bg-black/30~60` ×33 → `bg-surface-3` 或 `rgb(var(--overlay)/N)`（light 下自动反转）。

### 3.3 圆角/间距/阴影档次语义（治散点）

- 圆角：`rounded-md`（0.375）=控件/输入框、`rounded-lg`（0.5）=卡片/徽章、`rounded-xl`（0.75）=弹层/Hero；
  默认 `rounded`（675 处）按宿主语义归档。
- 阴影：18 处 tailwind `shadow-*` 直写 → `var(--shadow)`（`.card-hover` 已示范）。
- 间距不动 token 化（投入产出差），只随页面改造顺手归整。

### 3.4 清理（治 E9）

删 `App.css` 死文件；删 `darkMode:'class'` 无效配置；注释「四主题」→五主题（3 处）。

## 七、验收标准（可判定项，沿用 T-1042「看一眼即可判定」原则）

1. **主题健全性**：五主题逐一截图对照——任意页面无「不随主题变的色块/文字」（U0 起的硬性判据）。
2. **唯一性计数**：状态徽章做法=1（StatusBadge）、弹层实现=1（Modal）、页签样式 ≤2（Tabs 两 variant）、
   危险红=1 种写法；grep 可证。
3. **散点收敛计数**：`text-[Npx]` ≤50 处（白名单豁免）并逐期下降；原生 tailwind 状态色类名=0；
   内联 hex（白名单外）=0。
4. **三态体验**：StateView 覆盖的页面，加载=骨架屏、空态=图形+文案、错误=徽章+重试，
   文案全站唯一（「加载中…」）。
5. **无功能回归**：vitest 全绿 + build PASS + oxlint 触碰 0 error；AgentChat/Drafts/RunControl
   手工冒烟（WS 对话/草稿三闸流转/断点执行）各一遍；体验基线五条抽查（状态持久化键不变、
   三态不混用、长操作刷新入口在）。
6. **性能不倒退**：不新增运行时依赖；首屏 bundle 不显著增大（StateView/Toast/Badge 全站合计 <15KB）。

## 八、风险与缓解

| 风险 | 缓解 |
|------|------|
