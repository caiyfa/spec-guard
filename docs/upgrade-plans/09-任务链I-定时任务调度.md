# 任务链 I：定时任务调度

> 优先级：**P0**（业务闭环的定时运行环节，当前完全缺失）
> 并行性：✅ 独立，可与任务链 H 并行（H 负责 Agent 侧，I 负责调度侧）
> 预计工期：1 周
> 文档依赖：[总览](./00-总览与任务链编排.md)、[任务链 H](./08-任务链H-闭环编排与模式自动路由.md)（闭环流程）、[任务链 J](./10-任务链J-通知配置.md)（失败通知）

---

## 一、目标

让「一组场景（plan）」可以**定时自动运行**，失败时触发通知（接任务链 J）。

**用户决策**：工作台 UI 配置定时任务；执行走**引擎直跑**（不经 pytest）。

### 为什么引擎直跑而非 pytest

| 维度 | pytest 模式 | 引擎直跑（本链采用） |
|------|------------|---------------------|
| 依赖编排 | ❌ 无法表达「场景 A 失败 → 场景 B 跳过」 | ✅ `plans/{id}.yaml` 声明 DAG 依赖 |
| 中断通知 | ❌ 跑完才出结果 | ✅ 某环节失败立即触发通知 |
| 断点恢复 | ❌ | ✅ 引擎 save 变量 + 依赖状态管理 |
| CI 集成 | ✅ 适合 | 不需要（本链是工作台内调度） |

现有 `services/runner.py` 已是 pytest 子进程封装，本链新增**引擎直跑执行器**复用 `engine/scenario_runner` 的编排能力。

## 二、设计方案

### 技术选型：APScheduler

- **APScheduler (AsyncIOScheduler)**：轻量、与 FastAPI 异步生态契合、SQLite jobstore 持久化
- 新增依赖 `apscheduler>=3.10`（按 AGENTS.md「Ask First」需评审）
- 备选 Celery/RQ：过重（需 Redis/RabbitMQ  broker），SpecGuard 单机部署不需要

### 架构

```
workbench/backend/services/scheduler.py（新建）
   ├─ AsyncIOScheduler（jobstore=SQLite）
   ├─ 任务类型：
   │    ├─ run_plan(plan_id)        ← 定时跑一组场景（引擎直跑）
   │    └─ audit_workspace(ws)      ← 定时重新审计（可选，二期）
   ├─ 生命周期：FastAPI startup 启动 / shutdown 停止
   └─ 失败钩子：环节失败 → 调任务链 J 的通知

workbench/backend/services/plan_executor.py（新建）
   └─ 引擎直跑执行器：加载 plan YAML → scenario_runner 编排 → 逐场景执行
      → 某场景失败 → 按依赖图标记下游 skipped → 触发通知
```

### DB 表

```sql
CREATE TABLE IF NOT EXISTS scheduled_jobs (
    id TEXT PRIMARY KEY,             -- job-{uuid8}
    name TEXT NOT NULL,              -- 任务名（用户填）
    plan_id TEXT NOT NULL,           -- 关联的测试计划
    workspace TEXT NOT NULL,         -- 工作区
    cron TEXT NOT NULL,              -- cron 表达式（如 "0 2 * * *"）
    notify_config_id TEXT DEFAULT '',-- 关联通知配置（任务链 J）
    enabled INTEGER NOT NULL DEFAULT 1,
    created_by TEXT NOT NULL,        -- 工号
    created_at TEXT NOT NULL,
    last_run_at TEXT DEFAULT '',
    last_run_status TEXT DEFAULT '', -- success / failed / partial
    last_run_id TEXT DEFAULT ''      -- 关联报告
);
```

### 执行逻辑（引擎直跑）

```python
# services/plan_executor.py

async def execute_plan(plan_id: str, workspace: str, triggered_by: str = "schedule") -> dict:
    """引擎直跑一组场景（DAG 编排）。

    Returns:
        {"run_id": ..., "status": "success|failed|partial",
         "results": [{"scenario_id": ..., "status": ..., "error": ...}]}
    """
    plan = plan_store.load(plan_id)          # plans/{id}.yaml
    graph = dependency_graph.build(plan)     # DAG 拓扑
    results = []

    for scenario in graph.topological_order():
        if graph.is_blocked(scenario):        # 上游失败 → 跳过
            results.append({"scenario_id": scenario.id, "status": "skipped",
                            "reason": "上游失败"})
            continue
        try:
            r = await scenario_runner.run_single(scenario, workspace)
            results.append({"scenario_id": scenario.id, "status": r.status})
            if r.status == "failed":
                graph.mark_failed(scenario)   # 标记下游 blocked
                # 立即通知（不等全部跑完）
                await notify_plan_failure(plan_id, scenario, r, workspace)
        except Exception as e:
            graph.mark_failed(scenario)
            results.append({"scenario_id": scenario.id, "status": "error", "error": str(e)})
            await notify_plan_failure(plan_id, scenario, {"error": str(e)}, workspace)

    # 写报告到 {workspace}/.specguard/reports/{timestamp}/
    run_id = report_writer.write_plan_report(plan_id, results, workspace)
    status = "failed" if any(r["status"] in ("failed", "error") for r in results) \
             else "partial" if any(r["status"] == "skipped" for r in results) \
             else "success"
    return {"run_id": run_id, "status": status, "results": results}
```

**注意**：`scenario_runner` 当前是同步执行器，`run_single` 的异步封装用 `asyncio.to_thread` 或直接同步调用（APScheduler 的 AsyncIOScheduler 支持同步 job，会自动跑在线程池）。

## 三、风险与缓解

| 风险 | 缓解 |
|------|------|
| APScheduler 新依赖 | 评审；成熟库（10+ 年历史），无安全顾虑 |
| serve-prod.ps1 workers=1 限制与调度器兼容 | workers=1 单进程，调度器无多进程竞争问题；文档强调不可改 workers |
| 引擎直跑与 pytest 产物格式不一致 | 报告 writer 复用现有 `report_writer`，格式对齐 |
| 长时间运行的 plan 阻塞事件循环 | 同步 job 由 APScheduler 自动丢线程池；单 job 内部串行 |
