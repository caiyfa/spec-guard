## 2. 阶段一交付物：3 套设计方向 demo

每套方向一个**自包含静态 HTML**（零构建、双击可开、离线无 CDN），放 `docs/原型/ui-demo/{方向}/index.html`。
每套必须覆盖五个画板（同一文件内分区呈现）：

1. **🧭 flow 路径图**（第一优先级）——聚焦态 + 全图态两版；12 阶段网状拓扑（主路+条件分支+回边+双交互门）；
   四态（顺序正确/乱序/缺失/跳过）+ 当前阶段锚点 + 问题节点（⚠fail）+ 前置约束边；样例数据用真实结构
   （evals/flows/generate-scenario.flow.json 的 12 阶段名）
2. **AgentChat 会话页**——三栏：会话树 / 对话流（用户气泡+assistant 竖线块+工具卡片展开态+完成卡）/ 右侧页签面板
3. **图标体系页**——状态图标 6 枚（pass/fail/skip/blocked/warn/info）+ 工具图标 ≥12 枚（spec/scenario/draft/validate/
   knowledge/attribution/flow/todo/topic/registry/run/promote）+ 页签与操作图标；24px/16px 两档网格
4. **组件拼版**——StatusBadge / 按钮三档（primary/ghost/danger）/ 卡片 / 页签 / 弹层 / 空态（图形+文案+CTA）/ 骨架屏
5. **主题秀**——同一画板深色/浅色两版对照（色板用 CSS 变量组织，变量名对齐 themes.css 语义：surface-1/2/3、
   border、pass/fail/skip/blocked/warn/info、gray 阶）

三套方向（差异化立意，可改名不可同构）：

- **A「Instrument 仪表」**：深色优先的专业工具感（Linear/Vercel 气质）——细分割线、单强调色、描边徽章、
  信息靠排版分层而非色块
- **B「Paper 纸面」**：浅色优先的内容感——大留白、卡片浮起微阴影、标题字重对比、状态色克制
- **C「Terminal 终端」**：极客控制台——等宽字体主导、高对比、荧光状态色、字符感边框（┌─┐气质但精致化）

硬性约束：

- **图标全部内联 SVG 自绘**（stroke 1.5px、24 视窗、风格每套自洽）——三套共用一套图标语义、三种风格演绎；
  emoji 只允许出现在「现状对照」区。零依赖是红线（AGENTS.md Ask First）
- 每个 HTML 头注释写清：方向名 / 设计立意三句话 / 色板变量表 / 字体栈
- flow 图 demo 不限实现（纯 SVG/HTML 手绘均可）——若你判断 mermaid 表达力是「高级感」瓶颈，在文件头注释里
  给出一句话理由与替代渲染建议（供阶段二裁决）
- 附 `docs/原型/ui-demo/README.md`：三套对照说明 + 你的推荐意见与理由（总控人据此定稿）

## 3. 验收（总控人目检，任一不过打回）

- [ ] 三套方向差异一眼可辨（不是同构换皮）
- [ ] flow 图：聚焦/全图两态、四态、网状分支回边齐全；「当前」「错误」有明确视觉锚点；
      浅色与深色下节点文字都可读
- [ ] 图标：6 状态图标三套各自成体系，16px 下可辨不糊
- [ ] AgentChat 画板信息密度不劣于现状（紧凑不拥挤；顶栏/工具卡/页签有明确秩序）
- [ ] 无死角色：深浅对照无「看不清的字/融进背景的块」
- [ ] 每套设计立意三句话经得起追问（为什么这样分层/为什么这个色/为什么这个图标形态）
