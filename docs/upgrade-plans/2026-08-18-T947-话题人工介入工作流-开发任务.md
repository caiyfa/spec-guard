## 一、需求背景

飞书材料池的话题生成链路（同步落池 → LLM 聚类 → 候选话题 → 人工复核 → 共享图谱 → Agent 上下文）当前已自动直出（T-945：`sync_all` 尾部 + 每日校对 job 后异步触发聚类，候选直接落 `_candidate_topics.yaml`）。

**用户最终决策（2026-08-18）**：
1. **保留自动直出**——同步后自动聚类生成候选话题卡片，现有链路不变；
2. **补充人工介入口子**——新增"原文 → 分类草案 → 勾选 → 卡片"三阶段工作区，作为**修正/干预路径**：
   - 用户对某群某天的分类不满意时，可打开工作区看原文 + 重新 AI 分类 → 勾选接受的分段 → 重新生成话题卡片（覆盖该群该天的旧候选）；
   - 已生成的候选卡片：单卡**编辑**（title/summary 直接改）、单卡**重新生成**（该段重跑 LLM）。

**产品语义**：自动流保证"开箱即有话题"；介入流保证"错了能修、修得精确"。

**3. REST 端点（feishu_pool.py，登录即可）**：

| 端点 | 语义 |
|---|---|
| `GET  /api/feishu-pool/topics/drafts` | 全部草案（{items: {sha8/day: [段]}}） |
| `POST /api/feishu-pool/topics/draft` | body `{chat_sha8, day}` → 重新 AI 分类（text 模型未配置→明确 error 不 500）；返回该天新草案 |

| `PUT  /api/feishu-pool/topics/card` | body `{id, title?, summary?}` → edit_candidate |
