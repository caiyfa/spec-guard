## 1. 背景与目标

2026-08-14 已落地 9 项质量工具（前端 oxlint/vitest/knip + 仓库级 lefthook/jscpd + Python ruff/pytest-cov/hypothesis/vulture），基线报告落盘 `docs/质量基线/`，AGENTS.md 新增「质量基线与顺手修复（Boy Scout Rule）」章节。

**缺口**：基线只有 txt 原始输出，无可视化页面。查看问题要翻文本文件，清偿进度无法直观追踪。

**目标**：工作台新增「质量中心」页签——按需触发各工具扫描（机器可读 JSON），展示总览卡片 + 分工具明细 + 与首批基线的对比（清偿进度）。

## 3. 各工具原理与机器可读输出（数据来源层的关键）

所有工具都是 CLI，后端用 subprocess 调用、解析 stdout/文件即可。**除覆盖率外全是秒级**，覆盖率慢（specstd 约 6 分钟）必须走缓存。

| 工具 | 原理一句话 | 机器可读用法 | 实测耗时 |
|------|-----------|-------------|---------|
| oxlint | Rust 写的 AST linter，按规则类别批量开关 | `oxlint -c workbench/frontend/.oxlintrc.json --format json workbench/frontend/src` | ~1.3s / 60 文件 |
| ruff | Rust 写的 Python linter，规则码制（F401 等） | `ruff check --output-format json`（分布用 `--statistics`） | <1s |
| knip | 从 entry 建模块图，反向找未引用文件/导出/依赖 | `cd workbench/frontend && npx knip --reporter json` | ~10s |
| jscpd | token 序列滑窗查重（minTokens=80），按语言出重复率 | reporters 加 `json`，产物 `jscpd-report.json`（`--output` 指定目录，**输出目录须临时化勿污染仓库**） | ~0.2s |
| vulture | 静态分析定义-引用差集，confidence 分级 | 无 JSON，解析文本行 `file:line: message`（基线仅 8 行，正则即可） | <1s |
| pytest-cov | coverage.py 插桩，pytest 插件 | `--cov-report=json:<path>`（+ `term-missing`） | engine ~3s；specstd ~6min |
| hypothesis | 属性测试（随机输入验证不变量） | 不产生报告，属测试体系，页面无需接 | — |
| lefthook | git hooks 管理（Go 二进制） | 不产生报告，页面无需接 | — |

**约束（AGENTS.md Never 条款）**：扫描必须纯读——禁止触发任何 `--fix`/写回；jscpd/coverage 的产物文件写临时目录或运行产物目录（不入库）。

## 4. 页面需求（质量中心 QualityCenter）

### 4.1 前端

- 新页面 `workbench/frontend/src/pages/QualityCenter.tsx`，遵循 **Settings/EnvironmentConfig 的菜单+面板模式**（项目页签开发规范）。
- 菜单注册走**动态菜单 + RBAC** 体系（参考 MenuRoles 页与最近的菜单守卫约定），建议归属「测试/质量」类菜单分组，权限 `admin`/`tester` 可见。
- 布局：顶部总览卡片行（每工具一张：当前问题数 / 首批基线数 / 清偿差值↑↓）+ 下方工具明细页签（按文件聚合的表格 + 规则分布）；oxlint 的 8 个 error 与 ruff 的 F 类置顶标红。
- 每卡片带「重新扫描」按钮（单工具触发）+「最后扫描时间」。

### 4.2 后端

- 新 router `workbench/backend/routers/quality.py` + service `workbench/backend/services/quality_scan.py`：
  - `POST /api/quality/scan/{tool}` — 单工具按需扫描（tool ∈ oxlint/ruff/knip/jscpd/vulture），subprocess 调 CLI 解析 JSON 返回；超时上限 60s。
  - `GET /api/quality/latest` — 返回各工具最近一次扫描结果（内存/SQLite 缓存 + scanned_at），页面加载默认读这个，不自动触发扫描。
  - `POST /api/quality/scan/coverage` — **不同步执行**：写运行产物目录 + 记录任务态，或 v1 直接不做（见 §5 分期）。
- RBAC：复用 `require_role("admin", "tester")`（参照 settings.py 既有写法）。
- 工作区无关：质量基线是仓库级，**不走** X-SG-Workspace 透传。

### 4.3 不做清单（YAGNI）

- 不做历史趋势图（需持久化每次扫描计数，v2 再说）；不做自动定时扫描（schedules 体系可挂，v2）；不接 hypothesis/lefthook（无报告产物）；不在页面提供「一键 --fix」（违反报告模式治理）。
