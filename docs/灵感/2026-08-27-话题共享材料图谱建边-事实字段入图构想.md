# 话题共享材料图谱建边——事实字段入图构想

> 2026-08-27，T-1027《话题携带文档材料设计》拍板时总控人裁决：图谱建边本期不做、**将来肯定要建**——按灵感库协议入库挂重启条件。本文件沉淀设计共识，重启时直接照 §4 要点施工，不重新推导。

## 1. 背景与触发场景

T-1027 立项后，话题卡将携带 `shared_materials` 事实字段：群聊里客观分享过的云文档/妙记（确定性提取的链接 → 池内 fd-*/fm-* 快照或 null）。字段本身在话题卡/chips/agent 召回里已可消费；但 graph_index 图谱目前只有 T-992 mentions（FR 锚点）与 T-1015 references（人工确认）两类边——「这个话题源于群里分享过的那份文档」这条事实关系没有图表达，血缘视图看不到。

## 2. 需求本质（一句话）

把「聊天中客观发生的材料引用」物化为图的一条确定性边（tp →*fd/fm），让追溯链路天然覆盖话题↔材料的来源关系。

## 3. 结论（为何暂缓）

价值验证优先于图化：shared_materials 先走卡片展示 + agent 召回两条消费路验证有用性；且图是派生物（graph_index.db 可删可重建），从 `_topics.yaml` 事实随时可以重新投影，后建零数据损失——排序上理应让位。

## 4. 设计要点（重启时施工颗粒度）

- **边类型**：新增 `shared_in_chat` 类，区别 references（判断边）/mentions（锚点边）；src=tp id、dst=snapshot id，附 evidence（message_id + url + 时间窗）。
- **数据源即 T-1029 落地的 shared_materials 字段**：snapshot_ref=null 的孤儿引用不建边；有快照的直接映射 dst。
- **建边作业**：仿 T-1015 ④ 先例——graph_index/builder.py 加一个 edge 分派分支 + 节点存在守卫，从 _topics.yaml 全量确定性投影，幂等纯派生、随重建刷新。
- **前端可选**：依赖图/血缘视图对事实边与确认边用样式区分（实线/虚线徽标），不加新页面。
- **不动的东西**：material_links.yaml 存储语义、T-1015 推荐链路、LLM 建议路径均不涉及——这是纯确定性投影，无新增 LLM 消耗。

## 5. 重启条件（任一命中升级远期设计）

1. T-1029/T-1030 落地后，真实工作区 shared_materials 带 snapshot_ref 的事实积累到规模（经验阈值 ≥50 条），chips 平铺开始难以浏览；
2. agent 召回出现「跨话题追同一份文档」类查询（用户问「这份方案相关还有哪些讨论」时现有工具答不利索）；
3. 图谱消费方（面试场景/排查场景）明确要求展示话题↔材料溯源链。
