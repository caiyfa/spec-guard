## 一、背景

### 1.1 触发任务

为三个已上线的 P0 功能编写 SpecGuard 自动化测试场景：

| 功能 | 场景组 | 类型 |
|------|--------|------|
| 360 导入数值校验取消，空值/"-" 可导入且不丢其余数据 | EV-IMP-001/002 | 写型（Excel 导入） |
| 九宫格落位校验支持 0 / "-"（视为没有分数） | GP-IMP-001/002 | 写型（Excel 导入） |
| 已完成盘点会话退回按钮（PUT /{id}/revert） | IS-RVT-001/002/003 | 写型（状态流转） |

### 1.2 场景设计原则（第一批升级后确立）

1. **需求驱动**：断言预期只来自需求描述与 Spec FR，不从实现反推；
2. **无历史包袱**：不在场景 YAML 中硬编码任何环境数据 ID（活动/会话/人员）；每次运行自建数据、自清理；
3. **数据自给**：写型场景通过 unit 型 prep 场景经 API 创建活动→会话→人员，经 DAG `depends_on + exclusive` 为每个消费者提供独立实例，避免共享踩踏；
4. **不绕过引擎**：权限、环境差异等由引擎/环境配置兜底，场景只声明依赖。

### 1.3 缺口发现过程

按上述原则编写 prep 场景时，三个设计动作在现有引擎（v1.1.0）下**无合规表达手段**：

| 设计动作 | 需要的引擎能力 | 现状 |
|----------|---------------|------|
| 活动名称每次运行唯一（活动名全局唯一约束，作废才释放） | 运行时生成唯一值 | 插值只能引用已有变量，无法生成新值 |
| 从人员查询响应中取第一条记录 ID 进行锁定 | `{{resp.json.data.records[0].id}}` 数组下标插值 | `_resolve` 仅支持点号 dict 路径，规范 §3.4 已承诺但引擎未实现 |
| 环境差异常量外置（基座 ID / 专用工号 / corp 配置） | env yaml 自定义键经 `{{env.xxx}}` 引用 | `shared_ns["env"]` 仅暴露 `resource_code` 一个键 |
| 写接口（建活动/会话）所需管理资源码权限 | 账号权限预置 + 启动自检 | SIT 默认账号在 TDM_INV_ACTIVITY 下无权限，运行期才暴露 |

**曾评估并放弃的绕开方案**（均会产生历史包袱，与原则 2 冲突）：
- 硬编码 SIT 固定活动/会话 ID → 环境耦合，换环境即失效；
- 运行前由 Agent 直接调 API 预置数据 → 场景失去自包含性，无法独立重复运行；
- db_query `SELECT UNIX_TIMESTAMP()` 取唯一后缀 → 结果行引用仍需数组下标（REQ-1），循环依赖。

## 三、REQ-1（P0）：变量插值支持数组下标

### 现状证据

`tests/specguard/engine/scenario_runner.py::_resolve`（约 L137-146）：

```python
def _resolve(expr, ns):
    """点号路径取值：emp.no → ns['emp']['no']"""
    parts = expr.strip().split(".")
    cur = ns
    for p in parts:
        if isinstance(cur, dict) and p in cur:
            cur = cur[p]
        else:
            raise KeyError(...)          # ← 遇到 list 必抛 KeyError
```

`{{persons_q.json.data.records[0].id}}` 中 `"records[0]"` 不是 dict 键 → 中断。**规范 §3.4 已文档化数组插值（`{{resp.json.data.gridPlacement[0].activityId}}`），文档与引擎不一致。**

### 阻塞场景

```yaml
# IS-PREP-003：查询会话人员 → 锁定第一条（完成会话前置条件：至少 1 名已锁定人员）
- call: {method: POST, path: /api/inventory/persons/query, json: {sessionId: "..."}, save: persons_q}
- call:
    method: PUT
    path: "/api/inventory/persons/{{persons_q.json.data.records[0].id}}/lock"   # ← 当前 KeyError
```

### 建议实现

`_resolve` 路径段兼容 `name[N]`（支持负索引），或对整表达式 jsonpath 兜底（`jsonpath_parse("$." + expr)`，引擎已有 jsonpath 依赖，复用 `_jsonpath_find` 同款解析器）：

```python
def _resolve(expr, ns):
    try:
        return _resolve_dotted(expr, ns)                    # 现有点号路径（快路径）
    except (KeyError, TypeError):
        matches = jsonpath_parse(f"$.{expr}").find(ns)      # 兜底：数组下标/通配
        if not matches:
            raise KeyError(f"变量未定义: {expr}")
        return matches[0].value
```

### 验收标准

- `{{rows[0].id}}`、`{{rows[-1].ts}}`、`{{resp.json.data.records[0].id}}` 正确取值
- 存量点号路径（`{{emp.no}}`、`{{session.json.data.id}}`）行为回归不变
- 规范 §3.4 文档示例可直接运行

## 四、REQ-2（P0）：内置变量函数（唯一命名）

### 背景

盘点活动名称全局唯一（作废才释放名称，PLF-11）。写型 prep 场景每次运行创建新活动，名称必须唯一，否则第二次运行即 409。引擎目前没有任何「运行时生成新值」的手段（`set_var` 只能做变量间插值）。

### 建议语法

新增 `fn` 命名空间，`_resolve` 前置拦截：

```python
_FNS = {
    "fn.timestamp":  lambda: str(int(time.time())),      # 秒级时间戳
    "fn.date":       lambda: time.strftime("%Y%m%d"),
    "fn.uuid_short": lambda: uuid.uuid4().hex[:8],
}

def _resolve(expr, ns):
    if expr in _FNS:
        return _FNS[expr]()
    ...
```

### 典型用法

```yaml
flow:
  - set_var: {vars: {activity_name: "SG导入校验-{{fn.timestamp}}"}}
  - call:
      method: POST
      path: /api/system/activities
      json: {activityName: "{{activity_name}}", ...}
```

### 验收标准

- 同一步骤内 `{{fn.timestamp}}` 渲染为当前秒级时间戳字符串
- 两次独立渲染值单调不减（允许同秒相等）
- 嵌入字符串拼接（`"SG-{{fn.timestamp}}"`) 与完全匹配（保留类型）两种模式均正确

## 五、REQ-3（P1）：环境配置自定义段全量暴露

### 现状证据

`RunContext.__init__`（约 L90-92）：

```python
self.shared_ns["env"] = {
    "resource_code": env_config.get("default_resource_code", "TDM_SNAPSHOT_ARCHIVE"),
}
```

仅暴露一个键。env yaml 中其他配置（tdm_base、accounts 等）场景不可见，环境差异常量（如 UAT 与 SIT 的基座活动 ID 不同）无法外置，只能硬编码进场景。

### 建议实现

env yaml 支持 `vars:` 自定义段，整体挂载：

```yaml
# systems/tdm/config/env.sit.yaml
vars:
  fixture_corp: {code: "1002", name: "远东租赁"}
  fixture_emp_nos: ["90024713", "90027339", "90027338"]
```

```python
# RunContext.__init__
self.shared_ns["env"] = {
    "resource_code": env_config.get("default_resource_code", "TDM_SNAPSHOT_ARCHIVE"),
    "vars": env_config.get("vars", {}),
}
```

场景引用：`{{env.vars.fixture_corp.code}}`、`{{env.vars.fixture_emp_nos}}`（list 整体替换依赖 render 完全匹配分支，已实现）。

### 验收标准

- `vars` 段 dict/list/标量均可经 `{{env.vars.*}}` 引用
- env yaml 无 `vars` 段时渲染为空 dict，不报错

## 六、REQ-4（P1）：写型账号权限预置标准 + 启动自检

### 背景与证据

SIT 默认账号（caiyunfei/90024166）在写接口所需资源码下无权限：

```
POST /api/permission/auth/data-info {"empNo":"90024166","resourceCode":"TDM_INV_ACTIVITY"}
→ {"status":"400001","message":"没有资源(TDM_INV_ACTIVITY)权限"}
```

导致 `POST /api/system/activities` 返回业务码 500000「当前用户无平台权限，无法创建活动」。**按职责边界，权限是引擎/环境配置的责任，场景侧只引用账号别名，不应感知权限细节。**

### 建议方案（两件套）

1. **环境预置标准**：SIT 为测试账号绑定写型资源码全集（TDM_INV_ACTIVITY / TDM_SNAPSHOT_ARCHIVE / TDM_GRID_RESULT / TDM_INV_OPERATION 等），纳入环境交付 checklist；
2. **启动权限自检**：引擎 session 启动时对 `accounts` 中每个账号 + 场景库引用到的资源码集合，执行一次 `data-info` 探活，输出权限摘要表；缺失时在**运行报告首屏**标注 ENV 缺陷（区别于产品缺陷 FAIL），避免运行期以业务码 500000 形式模糊失败。

### 验收标准

- 写型 prep 场景（建活动/建会话/锁定/导入）在 SIT 直接 PASS
- 权限缺失时报告首屏可见「ENV-权限缺陷：账号 X 缺资源码 Y」明确提示
