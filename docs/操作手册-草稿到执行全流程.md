# SpecGuard 操作手册：从对话产出到测试执行（K-046 全流程）

> 适用版本：K-046 之后。覆盖「Agent 对话产草稿 → 编排 DAG → 执行测试」完整工作流。
> 核心原则：**三道闸不可绕**（人工评审 → 格式校验 → 发布门禁），草稿的一切编辑/连线/试跑都发生在沙箱，入库必经 promote。

---

## 一、全流程地图

```
🤖 Agent 对话                📝 草稿评审                🔀 DAG 编排              ▶️ 执行控制
─────────────              ─────────────             ─────────────           ─────────────
说需求/传信息包      ──▶    微调（表单/YAML）    ──▶    聚焦新节点        ──▶    勾选直接跑
Agent 写草稿               💡依赖建议一键连线          画布连线/建议连线          或从计划装载
（自动带拓扑设计）          ▶ 试跑（未入库先验证）      框选「执行选中」           轻量选项加速
                           ① 格式校验                 （跳执行控制）
                           ② 入库（自动跳 DAG）
```

每一步都不是死路：入库后自动跳 DAG 聚焦新节点；DAG 框选后一键跳执行控制预选。

---

## 二、第一步：Agent 对话产出草稿

1. 左侧菜单 **🤖 Agent → 对话**，进入 generate 模式（或直接说「生成 xx 场景」）。
2. 多场景时 Agent 会先做 **DAG 拓扑设计**（prep/消费划分 + depends_on + 变量契约）并请你确认。
3. 确认后 Agent 逐个生成 → `validate` 校验 → 写入 drafts/ 草稿区。
4. 生成后 Agent 会调 **suggest_deps**（确定性引擎）复核是否有遗漏的依赖边。
5. 草稿出现在 **🤖 Agent → 草稿评审** 列表，带 📦 信息包溯源标记。

> 对话里也可以直接让 Agent「试跑一下」（run_scenario 工具，草稿未入库也能跑）。

---

## 三、第二步：草稿评审（可微调、可连线、可试跑）

进入 **🤖 Agent → 草稿评审**，选中左侧草稿：

| 操作 | 说明 |
|------|------|
| **编辑微调** | 右侧是表单/YAML 双模式编辑器（与 DAG 抽屉同一组件）。表单模式按 Tab 改步骤/断言；YAML 模式直接改文本。💾 保存只写沙箱（自动 .bak 备份，可恢复） |
| **💡 依赖建议** | 编辑器上方自动显示建议边：高置信（你引用了 `{{某场景.变量}}`）/ 中置信（变量名匹配）。点「采纳」即写入 depends_on（文本外科手术，保留注释） |
| **▶ 试跑** | 未入库先验证：按依赖闭包真实执行目标环境（会产生真实数据），闭包内每个场景的 verdict 内联展示；FAIL 可去 Agent 对话 debug |
| **① 格式校验** | 与入库同一校验器，PASS 才能入库 |
| **② 评审通过 · 入库** | 选目标模块（可新建）→ 格式校验 → 契约基线 → 发布门禁，任一失败自动回滚。成功后**自动跳转 DAG 编排并聚焦新节点** |
| **废弃** | 移入 `drafts/_trash/`（可人工恢复） |

> ⚠️ 未解析引用提示：插值根找不到生产者时列出（可能是引擎内置变量如 `{{random:6}}`，也可能是真悬空引用，需人工判断）。

---

## 四、第三步：DAG 编排（画布 + 建议双通道）

进入 **🧩 场景 → DAG 编排**（或入库后自动跳入）：

- **聚焦**：入库跳转带来的新节点带蓝色高亮环并自动居中。
- **连线**：从上游节点拖到下游节点（depends_on 写在下游），自动环预检；选边按 Delete 删边。
- **建议连线**：点击任意节点，抽屉顶部显示该节点的 💡 依赖建议（同草稿页引擎），一键采纳。
- **编辑**：点击节点 → 抽屉内表单/YAML 编辑器直接改库内场景。
- **框选执行**：Shift 拖框选 / Ctrl 点选多个节点 → 工具栏出现「▶ 执行选中（N）」→ 跳执行控制并预选。

---

## 五、第四步：执行控制（选择优先，计划可选）

进入 **▶️ 执行 → 执行控制**（或 DAG 框选跳入）：

1. **勾选场景**：中间列表支持搜索 + 模块过滤 + 全选当前/清空；从 DAG 跳入时已自动预选。
2. **确认执行上下文**：触发按钮旁的上下文条显示环境与**闭包规模**（选中 N + 连带上游 K 个）——引擎按依赖闭包执行，上游 prep 会先跑。
3. **轻量选项**（按需）：
   - `仅准备`：只跑上游数据准备场景；
   - `上游不断言`：上游只跑 flow 不做 verify，闭包执行更快。
4. **🚀 执行选中（N）**：直接触发（后端 pytest `-k "A or B"`，无需计划）。
5. **从计划装载**（可选）：顶部下拉选计划 → 勾选自动填为该计划场景清单；**不改动**则走计划路径（保留计划归档/断点/env），**改动过**则按勾选直跑（界面有提示）。
6. **高级（按范围执行）**：折叠区，支持全量 / 标签 / 单场景表达式 / 离线引擎自测。
7. 执行中：实时日志流 + 勾选列表上的 verdict 图标（✓/✗/⊘）；他人执行时自动排队（FIFO，可取消自己的排队项）。

> 断点调试：计划内可配断点场景，命中后暂停，面板展示已完成/最近结果/输出尾部，「放行继续」逐批推进。

## 六、常见问题

| 问题 | 答案 |
|------|------|
| 草稿改坏了怎么办 | 保存时自动留 `.bak`（同目录 `文件名.yaml.bak`），人工改回即可 |
| 试跑和正式执行的区别 | 试跑 = 沙箱内单草稿闭包直跑（in-process，豁免 covers 闸）；正式执行 = pytest 全链路（有 covers 前置闸、报告归档、队列） |
| 为什么建议数是 0 | 说明该场景的插值引用都已有对应依赖边覆盖——引擎没遗漏，不是功能失效 |
| 排队时轻量选项生效吗 | 不生效（队列表不存这两项），轮到执行时按默认跑 |
| 入库失败怎么办 | 看报错阶段：格式校验 → 按 findings 修；发布门禁 → 跑 `python release_check.py` 看具体闸项；均自动回滚不会产生半截入库 |
