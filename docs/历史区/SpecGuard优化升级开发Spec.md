# SpecGuard 优化升级开发 Spec

> 创建时间：2026-07-27
> 输入文档：[SpecGuard验收期优化点总表.md](./SpecGuard验收期优化点总表.md)
> 开发模式：分阶段交付，每阶段设置**逻辑门**（Gate），用户验收通过后方可进入下一阶段

---

## 总览

共 11 项优化点，按功能优先顺序拆解为 **4 个阶段 + 1 个甜点池**：

| 阶段 | 主题 | 优化点 | 性质 | 预计交付物 |
|------|------|--------|------|-----------|
| **G1** | 基础设施 | 8.2 模型配置、8.1 会话绑定 | 前置依赖 | LLM 配置 UI + 会话工作区隔离 |
| **G2** | 场景创建流水线 | 4.1 渐进式流水线、4.2+8.4 工作模式 | **核心功能** | 场景创建向导 + Mode 系统 |
| **G3** | 体验增强 | 8.3 Compaction、8.5 Skills | 增强 | 长对话支持 + 技能系统 |
| **G4** | 甜点池 | 8.6、1.1、1.2 | 锦上添花 | 按需选做 |
| - | 架构决策 | 2.1 文件归属 | 非开发 | 独立评审 |

## 阶段 G1：基础设施

> **目标**：让 Agent 能在正确的上下文中运行起来。
> 没有这两项，后续所有 Agent 功能都无法正常工作。

### G1-1：大模型配置可视化 + 热加载

**对应优化点**：8.2
**优先级**：P0（一切 Agent 功能的前置）

**现状**：
- `SG_LLM_BASE_URL` / `SG_LLM_API_KEY` / `SG_LLM_MODEL` 环境变量，进程启动后固定
- `LLMClient.__init__` 一次性读入，不支持运行时更新

**验收标准**：

| # | 验收项 | 验证方式 |
|---|--------|---------|
| 1 | 环境设置页面有「大模型配置」区块，含 5 个字段（base_url / api_key / model / timeout / temperature） | 前端操作 |
| 2 | 每个字段有样例值和说明文案 | 前端检查 |
| 3 | 保存后 `POST /api/settings/llm-config` 即时生效，无需重启 | 切换模型后发消息验证 |
| 4 | 配置持久化到数据库，重启后保留 | 重启服务后检查 |
| 5 | 保存前自动探测连通性（发 `"hi"` 验证），失败给出明确提示 | 填错地址验证 |
| 6 | 未配置 UI 配置时回退到环境变量 | 清空 DB 配置后验证 |
| 7 | 环境变量存在时 UI 显示「当前由环境变量控制」提示 | 设置环境变量后检查 |

**涉及改动**：

| 层 | 文件 | 改动 |
|----|------|------|
| 后端 | `workbench/backend/services/llm_config.py` | **新建**：配置 CRUD + 热加载 |
| 后端 | `workbench/backend/routers/settings.py` | **新建**或扩展：配置读写端点 + 连通性探测 |
| 后端 | `agent/llm_client.py` | 支持 `reload()` 或配置版本检测 |
| 前端 | `workbench/frontend/src/pages/Settings.tsx` | 新增 LLM 配置区块 |

### G1-2：会话管理：用户 + 工作区绑定

**对应优化点**：8.1
**优先级**：P0（多用户 + 多工作区场景必须）

**现状**：
- 会话存储 `agent/sessions/{emp_no}/{session_id}.jsonl`，无工作区维度
- 无会话元数据（工作区、创建时间、摘要）

**验收标准**：

| # | 验收项 | 验证方式 |
|---|--------|---------|
| 1 | 新会话存储路径为 `agent/sessions/{emp_no}/{workspace}/{session_id}.jsonl` | 文件系统检查 |
| 2 | 会话列表 API 支持按工作区筛选（query param `?workspace=xxx`） | API 调用验证 |
| 3 | 前端会话侧边栏可按工作区过滤 | 前端操作 |
| 4 | admin 视图支持按工作区聚合查看 | admin 账号验证 |
| 5 | 旧格式会话（无工作区目录）自动迁移或兼容读取 | 存量数据验证 |
| 6 | 会话元数据记录 emp_no / workspace / created_at | JSONL 首行检查 |

**涉及改动**：

| 层 | 文件 | 改动 |
|----|------|------|
| 后端 | `workbench/backend/routers/agent.py` | 会话 CRUD 加 workspace 维度 |
| 后端 | `agent/session.py` | SessionManager 支持工作区子目录 + 元数据 |
| 前端 | `workbench/frontend/src/pages/AgentChat.tsx` | 会话列表加工作区筛选 |

## 阶段 G2：场景创建流水线 + 工作模式系统

> **目标**：实现「从 Spec 文件到测试编排」的完整工作流——这是本次升级的核心功能。
> 用户无需手写 YAML，从任意格式的需求文档出发，通过 Agent 引导完成场景创建。

### G2-1：场景创建流水线（渐进式向导）

**对应优化点**：4.1
**优先级**：P0（核心功能）

**现状**：
- 无「新建场景」入口，只能编辑已有 YAML
- Spec 文件与场景无显式关联，covers 锚点靠人工声明
- 不支持非 SpecGuard 格式的文档

**功能流程**：

```
步骤 1：新建场景
  │   - 输入场景名称、所属模块
  │   - 创建空的场景元数据记录
  │
  ▼
步骤 2：选择基础信息包（Spec 文件关联）
  │   - 从工作区文件树勾选相关文档（多选、多类型）
  │   - 支持 Markdown / Word / Excel / JSON / YAML / 纯文本
  │   - 文件列表持久化为该场景的「基础信息包」
  │
  ▼
步骤 3：Agent 分析 → 生成基础单元测试
  │   - Agent 读取基础信息包全部文件
  │   - 自动提取 FR/AC 锚点
  │   - 生成单元测试场景 YAML 草稿（写入 drafts/）
  │   - 如发现信息不足 → 会话中主动提问
  │   - 用户确认补充文件 → 自动加入基础信息包
  │
  ▼
步骤 4：场景编排（DAG 画布）
  │   - 在 DAG 画布上编排场景执行顺序
  │   - 设置依赖关系（shared/exclusive）
  │
  ▼
步骤 5：执行与验证
```

**验收标准**：

| # | 验收项 | 验证方式 |
|---|--------|---------|
| 1 | 有「新建场景」入口（按钮或页面），可输入名称和模块 | 前端操作 |
| 2 | 步骤 2 可从工作区文件树勾选多个文件，支持多类型 | 勾选 spec.md + Excel 验证 |
| 3 | 基础信息包持久化（场景 ↔ 文件列表映射），Agent 会话可随时回溯 | 重新进入场景验证 |
| 4 | Agent 能读取选中的文件内容并生成场景 YAML 草稿 | 端到端走通 |
| 5 | Agent 发现信息不足时在会话中提问，用户确认后自动补充文件到基础信息包 | 模拟缺失场景验证 |
| 6 | 生成的草稿进入 drafts/ 目录，可通过现有评审流程入库 | 草稿管理页面检查 |
| 7 | 步骤 4 可跳转到 DAG 编辑器进行编排 | 前端操作 |
| 8 | 非 SpecGuard 格式的文件（如纯文本 PRD）也能作为基础信息接入 | 用 txt 文件验证 |

**涉及改动**：

| 层 | 文件 | 改动 |
|----|------|------|
| 后端 | `workbench/backend/services/scenario_meta.py` | **新建**：场景元数据（基础信息包）CRUD |
| 后端 | `workbench/backend/routers/scenarios.py` | 新场景创建端点 |
| 后端 | `agent/runtime.py` | Agent 读取基础信息包的上下文注入 |
| 前端 | `workbench/frontend/src/pages/ScenarioCreate.tsx` | **新建**：创建向导页面 |
| 前端 | `workbench/frontend/src/pages/AgentChat.tsx` | Agent 会话中展示基础信息包 |

### G2-2：工作模式系统（合并 4.2 + 8.4）

**对应优化点**：4.2 + 8.4
**优先级**：P0（与 G2-1 配套，没有模式区分 Agent 行为不可控）

**现状**：
- Agent 只有一种模式，所有工具始终可用
- system prompt 固定不变
- 无模式切换 UI

**设计**：借鉴 OpenCode 的 Mode 机制，Markdown 文件定义模式

**验收标准**：

| # | 验收项 | 验证方式 |
|---|--------|---------|
| 1 | `agent/modes/` 目录下可通过 Markdown 文件定义模式（YAML 前置 + 正文 prompt） | 文件系统检查 |
| 2 | 内置 4 种模式：场景生成 / 场景调试 / 只读分析 / 自由对话 | 模式列表检查 |
| 3 | 每种模式独立配置：temperature、可用 MCP 工具白名单、system prompt 片段 | 切换模式后 Agent 行为变化 |
| 4 | 前端 AgentChat 页面有模式切换 UI（Tab 或下拉选择） | 前端操作 |
| 5 | 模式切换后 Agent 的 system prompt 和可用工具实时更新 | 切换后对比 |
| 6 | 场景生成模式下 Agent 只能使用生成相关工具（read_spec / query_registry / validate / write_draft） | 在生成模式要求 Agent 做无关操作验证 |
| 7 | 只读分析模式下 Agent 无法写文件 | 验证写操作被拒绝 |

**模式定义示例**（`agent/modes/generate.md`）：

```markdown
---
temperature: 0.3
tools:
  - read_spec
  - query_registry
  - validate
  - write_draft
---
你是场景生成助手。读取用户提供的基础信息包文件，
自动提取 FR/AC 锚点，生成符合 SpecGuard 格式的单元测试场景 YAML 草稿。
发现信息不足时主动向用户提问。
```

**涉及改动**：

| 层 | 文件 | 改动 |
|----|------|------|
| 后端 | `agent/modes/generate.md` | **新建**：场景生成模式定义 |
| 后端 | `agent/modes/debug.md` | **新建**：场景调试模式定义 |
| 后端 | `agent/modes/analyze.md` | **新建**：只读分析模式定义 |
| 后端 | `agent/modes/chat.md` | **新建**：自由对话模式定义 |
| 后端 | `agent/mode_loader.py` | **新建**：模式文件加载器 |
| 后端 | `agent/runtime.py` | 支持按模式过滤工具 + 动态 prompt |
| 前端 | `workbench/frontend/src/pages/AgentChat.tsx` | 模式切换 UI |

## 阶段 G3：体验增强

> **目标**：解决长对话熔断和流程指令硬编码问题，提升 Agent 可用性。
> 本阶段不引入新功能入口，属于核心功能的体验优化。

### G3-1：会话上下文 Compaction

**对应优化点**：8.3
**优先级**：P1

**现状**：
- `max_turns=12` 熔断，长对话直接截断
- 无历史压缩，大段 spec 文件内容占据 token

**验收标准**：

| # | 验收项 | 验证方式 |
|---|--------|---------|
| 1 | 超过阈值（如 8 轮）时自动压缩旧消息为摘要 | 构造 12+ 轮对话验证 |
| 2 | 压缩时保留最近 3-5 轮原始消息 | 检查上下文构成 |
| 3 | 压缩时保留文件操作摘要（读了哪些 spec 文件、写了哪些 draft） | 检查压缩摘要内容 |
| 4 | 压缩后对话不中断，Agent 能继续引用之前的上下文 | 长对话连续性验证 |
| 5 | 摘要消息标记为 `_type: "compaction_summary"` | JSONL 检查 |

**涉及改动**：

| 层 | 文件 | 改动 |
|----|------|------|
| 后端 | `agent/compactor.py` | **新建**：会话压缩器 |
| 后端 | `agent/session.py` | 加载时处理 compaction_summary 消息 |
| 后端 | `agent/runtime.py` | 超过阈值时触发压缩 |

---

### G3-2：Skills 系统

**对应优化点**：8.5
**优先级**：P1

**现状**：
- system prompt 中的流程指令硬编码在 Python 代码里，修改需改代码
- 无可复用的能力声明机制

**验收标准**：

| # | 验收项 | 验证方式 |
|---|--------|---------|
| 1 | `agent/skills/` 目录支持 SKILL.md 文件（YAML 前置 + Markdown 正文） | 文件系统检查 |
| 2 | 内置至少 3 个技能：场景生成 / 合规校验 / 失败分析 | 技能列表检查 |
| 3 | Skills 内容注入 system prompt 的 XML 块，模型可见 | 对话中验证模型能感知 |
| 4 | 新增 SKILL.md 文件后无需重启即可生效（或重启一次后生效） | 添加新技能验证 |
| 5 | 前端可展示可用技能列表 | 前端检查 |

**涉及改动**：

| 层 | 文件 | 改动 |
|----|------|------|
| 后端 | `agent/skills/generate-scenario.md` | **新建** |
| 后端 | `agent/skills/validate-conformance.md` | **新建** |
| 后端 | `agent/skills/debug-failure.md` | **新建** |
| 后端 | `agent/skill_loader.py` | **新建**：技能文件加载器 |
| 后端 | `agent/runtime.py` | system prompt 构建时注入 skills |
| 前端 | `workbench/frontend/src/pages/AgentChat.tsx` | 技能列表展示 |

## 阶段 G4：甜点池（按需选做）

> 以下优化点为锦上添花，不阻塞核心流程。G3 验收通过后按优先级选做。

### 甜点 A：操作撤销 + 成本可观测

**对应优化点**：8.6
**优先级**：P2

- Agent 写 draft 前自动备份（`.bak`），支持 `/undo` 回滚
- 前端 AgentChat 底部显示实时 TPS、token 消耗、累计成本
- 会话导出 JSON/HTML

### 甜点 B：Git 克隆自定义克隆目录

**对应优化点**：1.1 + 1.2
**优先级**：P2

- Git 克隆时可选克隆目录（留空走默认 `_clones/{name}/`）
- 路径穿越防护
- 统一两种注册途径的交互模型

## 架构决策（不纳入开发阶段）

### AD-1：SpecGuard 产生的文件归属策略

**对应优化点**：2.1
**性质**：架构决策，非开发任务

需独立评审确定：
- 场景/计划/报告/草稿的归属边界
- 是否需要推送到 Spec 仓库
- Git 操作权限模型

建议在 G2 验收后、G3 开始前评审，因为场景创建流水线（G2-1）会产生更多文件类型。
