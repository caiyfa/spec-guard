## 三、子任务 A-2：Token 级 Compaction（含中文估算）

### 背景

G3-1 实现了 Compaction（`agent/compactor.py`），但 `should_compact` 用 `COMPACTION_THRESHOLD=16` 条消息判断（`compactor.py:16`）。

**问题**：
1. **system prompt 体量大**：全量注入 format_spec + AGENTS.md + skills XML，单 system prompt 3-8K token。8 轮对话（16 条消息）下可能超 64K 上下文窗口而 compaction 未触发。
2. **`should_compact` 过滤逻辑 bug**（`compactor.py:28-31`）：`or` 条件导致普通 system 消息被错误保留，应改为 `and`。
3. **【修正补充】中文 token 估算偏差**：初版 `estimate_tokens = len(text)/4` 对中文严重低估（中文 1 字约 1-2 token，`len("你好")=2`，`2/4=0`，但实际约 3-4 token）。

### 设计方案

#### 修正的 Token 估算函数（区分中英文）

```python
def estimate_tokens(text: str) -> int:
    """估算文本 token 数（区分中英文）。

    【修正】初版用 len(text)/4，对中文严重低估：
      - 中文 1 字 ≈ 1-2 token（GPT 系列约 1.5）
      - 英文 4 字符 ≈ 1 token
      - 混合文本需分开统计

    参考 OpenCode 的 token.ts（chars/4），但 SpecGuard 是中文场景，必须修正。
    """
    if not text:
        return 0
    # 统计中文字符（CJK 统一表意文字 + 常用标点）
    chinese_chars = sum(1 for c in text if '\u4e00' <= c <= '\u9fff' or '\u3000' <= c <= '\u303f' or '\uff00' <= c <= '\uffef')
    non_chinese = len(text) - chinese_chars
    # 中文 1 字 ≈ 1.5 token（保守），英文/数字 4 字符 ≈ 1 token
    estimated = int(chinese_chars * 1.5 + non_chinese / 4)
    return max(1, estimated)


def estimate_message_tokens(message: dict) -> int:
    """估算单条消息的 token 数（含 content + tool_calls）。"""
    total = 4  # 每条消息的元数据开销
    content = message.get("content")
    if isinstance(content, str):
        total += estimate_tokens(content)
    elif isinstance(content, list):
        for part in content:
            total += estimate_tokens(str(part))
    # tool_calls 的 arguments 也算
    for tc in message.get("tool_calls", []) or []:
        args = tc.get("function", {}).get("arguments", "")
        total += estimate_tokens(args) if isinstance(args, str) else estimate_tokens(str(args))
    return total
```

#### 阈值判断改造（修复 or→and bug）

```python
COMPACTION_RATIO = 0.7  # 占比 max_context_tokens 的 70%
MIN_MESSAGES_BEFORE_COMPACT = 8  # 保底消息数

def should_compact(messages: list[dict], max_context_tokens: int = 0) -> bool:
    """判断是否需要压缩（token 级阈值 + 消息数保底）。"""
    # 【修复 bug】正确排除 system 首条与 compaction_summary（or → and）
    conversation_msgs = [
        m for m in messages
        if not (m.get("role") == "system" and m.get("_type") in (None, "compaction_summary"))
    ]
    if len(conversation_msgs) < MIN_MESSAGES_BEFORE_COMPACT:
        return False

    if max_context_tokens <= 0:
        # 回退：消息数阈值（向后兼容）
        return len(conversation_msgs) > 16

    estimated = sum(estimate_message_tokens(m) for m in messages)
    return estimated >= int(max_context_tokens * COMPACTION_RATIO)
```

#### KEEP_RECENT 动态化（按 token 预算）

```python
def _calc_keep_count(conversation: list[dict], reserve_tokens: int) -> int:
    """从尾部累计，保留不超过 reserve_tokens 的消息数。"""
    acc = 0
    count = 0
    for m in reversed(conversation):
        t = estimate_message_tokens(m)
        if acc + t > reserve_tokens:
            break
        acc += t
        count += 1
    return max(count, 4)  # 至少保留 4 条（2 轮）

# compact() 内：reserve_tokens = max_context_tokens * 0.25
```

`runtime.py:195, 243` 调用 `should_compact` 时传入 `self.llm.max_context_tokens`：

    messages = compact(messages, self.llm)
