# 上传附件模型看不到——info_pack 引用绕圈链路 4 环全断

## 现象

- 会话：`20260824_172320_84d21cfa`（emp 90024166 / 工作区「人才发展」）
- 用户两批上传附件（13:12 三文档 → SG-META-0007；13:55 五文档 → SG-META-0008），
  均报告**上传成功**且前端引用 chip 正常显示
- 模型两轮均回答「没有看到新附件」，并自行调用 `info_pack(action=read, scenario_id=SG-META-0001)`
  读到一个无关旧信息包（AGENTS.md + person-profile/spec.md），还误认为那就是用户上传的文档
- 第一批实际同样未注入（被旧包内容掩盖，未当场发现）

## 证据链

1. **上传落盘成功**：`specguard-space/.specguard/info_packs/SG-META-0007.yaml`（3 文件，13:12:36）、
   `SG-META-0008.yaml`（5 文件，13:55:42）；用户消息 `references` 字段持久化正确指向
   （会话 JSONL 第 45/67/70 行）
2. **模型上下文从未出现新信息包 ID**：会话全文检索 `SG-META-0007/0008` 仅命中 references
   持久化字段（不进 LLM）；模型首次读到 `SG-META-0001` 是自己写的 tool_calls（第 49 行），
   来源是工具参数描述里的示例 ID（`info_pack.py`：「场景元数据 ID（如 SG-META-0001）」——
   示例恰好是真实存在的旧包）
3. **四环全断**（缺一即复现）：
   - 环 A `agent/runtime.py` 续会话分支：`messages = history` 直接采用历史，WS 层每条消息
     重建的 system prompt（含最新场景/信息包清单）被丢弃，`messages[0]` 永远是首条消息版本
   - 环 B `routers/agent.py` `_process_references`：info_pack 引用「只关联不注入」
     （ref_block 为空），且仅在 scenario_id 为空时接管——已绑定场景的会话新上传被静默忽略
   - 环 C `AgentChat.tsx` handleSend：`setScenarioId(packRef.path)` 异步 setState 后
     `ws.send` 用闭包旧值发送 `scenario_id`（stale closure）
   - 环 D 工具描述示例 ID 恰好真实存在，模型拿示例当真读了误导性内容

## 根因

附件传递链路设计偏离业界模式（配置/设计层）：业界主流（OpenAI `input_file` content part /
Anthropic `document` content block / ChatGPT 全量注入 / Cursor @ 展开 / Claude Code @-mention）
均为**附件内容直接注入上传那一轮 user message，模型当轮即见**；SpecGuard 走了
「落盘信息包 → 引用只关联 → system prompt 提示（还被 runtime 丢弃）→ 指望模型调 read_info_pack」
的绕圈链路，任何一环断裂即「模型看不到附件」。system prompt 不该承载轮次级附件数据
（既破坏语义又每轮重建成本高）；工具按需读取只应作大文件降级通道（同 T-933 material 模式）。

## 修复

TDD 先红后绿（6 新测试 + 1 存量测试更新语义；test_specstd 全量 1850 绿 / test_workbench 63 绿
+8 存量失败（stash 基线对比确认）/ 前端 tsc 无错 + vitest 106 绿）：

1. `_process_references`（routers/agent.py）：info_pack 引用**上传即关联 + 内容直接注入**
   `<references>` 块（与 file/draft 同通道：sha 标头、office 文档 file_preview 转文本、
   `_REF_MAX_FILE` 20KB/`_REF_MAX_TOTAL` 60KB 截断保护、空包/缺包注入可见提示）
2. `agent/runtime.py` 续会话：新 system_prompt 替换 history 首条 system 消息
   （每轮重建的场景上下文真正生效，修复 K-013 设计意图与实现的漂移）
3. `AgentChat.tsx` handleSend：本轮 `ws.send` 用同步计算的 `sidToSend`（不走闭包旧值）
4. 工具描述示例 ID 改为不存在的 `SG-META-XXXX` 格式（info_pack.py / draft_writer.py 共 4 处）

## 预防

- 附件/引用类数据一律随 user message 注入（轮次级数据不进 system prompt）；
  新增引用类型时对照 `_process_references` 四通道（file/draft/info_pack/material）选型：
  小文件直接注入，大文件走「标识 + 工具按需读」
- React 发送类 handler 中 setState 后同步使用值，必须用本地同步变量（stale closure 高发）
- 工具 schema 的示例值禁止使用真实存在的 ID/路径（改为 XXXX 占位格式）
- 排障动线：会话 JSONL 中检索关键 ID 的命中位置（仅持久化字段 = LLM 从未见过；
  出现在 tool_calls/结果 = 模型主动获取过）可直接区分「没注入」与「注入了没读」
