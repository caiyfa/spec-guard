# 2026-08-27 · T-1031/T-1032 辅助助手三缺陷——离线全绿、工作台实证拦获

## 现象

主库验收 feature/agent-aux：**离线门禁全绿**（specstd 注入版 1980 绿 0 跳、vitest 168、
build/engine 39+244/release PASS、ruff 持平），但工作台真轮次实证抓到三处功能级缺陷——

- **缺陷 C**：主会话脉络摘要永远 `mode=skeleton`，md 里内嵌
  `<!-- llm_error: 'LLMClient' object is not callable -->`（诚实降级把现场留下了）。
- **缺陷 A**：辅助提问的 user 消息里**永无** `<viewing_context>` 块；模型第一动作仍是
  搜场景库扑空（`scenario read → 场景不存在`），再靠父快照自纠——「查看指针」特性出厂即死。
- **缺陷 B**：切换主会话后辅助面板头部 sid 纹丝不动（粘死首个解析结果），且全 UI 无任何
  会话切换入口，旧 sql_assistant 辅助会话无路径恢复。

## 证据链

- **C**：`agent/sessions/90024166/人才发展/20260827_150916_9272e88b_digest.md` 内嵌
  llm_error 注释、`_digest.json` 在一次完整 LLM 轮次后仍 `mode=skeleton`；
  `workbench/backend/routers/agent.py` `_refresh_parent_digest_bg` 源码：局部闭包
  `_llm(system,user)` 定义后**从未使用**，`llm_call=use_llm` 传入的是 LLMClient 实例本身，
  而 `session_digest.refresh_digest` 以 `llm_call(system,user)` 函数形态调用。
- **A**：会话 JSONL 尾部 user 消息只有 `<parent_context>` 无 viewing 块；
  `AgentChat.tsx getViewing()` 要求 `activeSideTab.startsWith('file:')`——而用户打字
  必须先切到辅助面板，发送时刻活动签恒为 aux ⇒ focus_path 恒空、后端永不注入。
- **B**：四个主会话逐一打开，辅助面板头部 sid 均为同一值；`SqlAuxPanel.ensureSession`
  的 `if (!mainSessionId || sidRef.current) return` 守卫使 mainSessionId 变化后
  不再重新解析；后端 `/sessions/spawn` 幂等语义本身正常（同父+purpose 复用）。
- **单测为何全绿**：test_parent_digest 用可调用 stub 直接喂 `refresh_digest`（没经过
  routers 装配层）；SqlAuxPanel 测试只钉 stripRefBlock 文本剥离（不钉绑定生命周期）——
  三缺陷全部位于**被 mock 掉的装配/集成面上**。

## 根因

- C：装配层传参错误（实现层）——闭包定义了没用，把客户端实例当函数传入。
- A：焦点语义与用户操作时序矛盾（设计层）——「发送时刻的活动文件签」在合法操作流下必为假。
- B：组件生命周期粘滞（实现层）——守卫只防重复拉取，没回答「依赖 key 变化后谁重置」。
- 共性：三者都藏在离线单测 mock 掉的集成面上；**离线全绿 ≠ 功能可达**。

## 预防

- 后台任务/回调装配类代码：传「函数」还是「实例」必须在**装配层**放钉子
  （monkeypatch 真装配函数、捕获参数断言 callable），只测被调方防不住传错。
- 「随消息携带的上下文指针」类特性：设计时先画用户操作时序（打开文件→切面板→打字→
  发送），逐时刻断言焦点状态；UI 提示文案承诺的注入行为必须有端到端钉。
- 凡写 `if (ref.current) return` 类守卫，必须同答「依赖的 key 变化时谁负责重置」；
  跨父/跨 key 绑定测试要在**同一挂载内切换 key** 才测得到粘滞。
- 工作台功能验收必须包含真轮次实证并与磁盘产物对账（会话 JSONL/digest/报告）；
  落盘产物中的 `llm_error`/error 注释是静默降级的黑匣子，排障先 grep 它。
