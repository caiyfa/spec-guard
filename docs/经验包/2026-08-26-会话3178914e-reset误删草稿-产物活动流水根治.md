## 现象

- 会话 `20260825_151821_3178914e` 中，Agent 在草稿修复循环里**五次自调 `draft(action=reset)`**，清空全工作区草稿区——含总控人手写进入的 v0.3 修复版草稿，无确认、无区分会话归属，全部消失
- 用户视角：草稿区一夜回到零，连自己手工放的修复版也没了；文件系统无回收站，内容不可恢复

## 证据链

- 会话 JSONL（`agent/sessions/.../20260825_151821_3178914e.jsonl`）：五次 `draft(action=reset)` 工具调用记录，调用前 Agent 均先遭 `write_draft` 返回 `OVERWRITE_DENIED`（禁覆盖防呆）——重写无门后才走 reset 绕路
- 旧 `draft_writer.py` reset handler：全清草稿区目录，无会话过滤、无确认环节、无删除前留档
- 旧 `write_draft`：create 撞已存在文件即 `OVERWRITE_DENIED`，无 overwrite 出口——防呆设计在 Agent 自治循环里变成「逼向破坏性操作」的斜坡

## 根因

**引擎（工具语义设计层）**，双层叠加：

1. reset 全清语义且不分会话归属——Agent 工具路径的破坏面 = 全工作区，远超其会话职责边界
2. write 禁覆盖无出口——`OVERWRITE_DENIED` 把「整体重写」这一正当需求逼向 reset 绕路（防呆没有配安全出口）

单修任何一层都不够：只加 overwrite 仍留 reset 全清后门；只收窄 reset 仍留 Agent 重写无门。

## 修复（2026-08-26，0a2632a 主体 / 合并 cd6b788 / 前端回退 bc62c79）

- **产物活动流水** `sg_core/product_activity.py`：单表承载「会话↔产物↔版本链」（session_id/emp/workspace/action/version_no/sha + **content 全文快照**）——文件系统被清后 DB 仍是恢复事实源；session/emp/workspace 走 contextvar 零传参注入
- **reset 会话收窄**（draft_writer）：仅清当前会话写入的草稿，其他会话/手工草稿不动并如实报告 `skipped`；**无会话上下文拒绝执行**（不留「无会话=全清」后门）；删前进 `reset_delete` 流水留档
- **write mode=overwrite**：旧版自动备份 .bak 且进版本链——Agent 重写正道；create 禁覆盖防呆保留（逼 Agent 先读旧内容）
- **writing_feed 双源**：消息链重放为主体，DB 活动做版本号增强 + 长会话压缩时兜底卡片
- **验收裁决回退**：前端跨会话接管展示（全量渲染/外会话徽标/版本徽标）整体回退，面板维持本会话草稿口径；后端流水 + `/drafts/activity` + `/drafts/{filename}/versions` 端点保留为数据地基
- 联网钉案复验（会话 20260826_182235_ca9759c3）：reset 只清本会话 RS-A1/A2，手工 MANUAL-KEEP 与同区 HI-PERM 六件完好，`skipped` 如实列出；reset_delete 行含 177B 全文快照；overwrite 后版本链 v1 create→v2 reset_delete→v3 create→v4 overwrite 端点可查
