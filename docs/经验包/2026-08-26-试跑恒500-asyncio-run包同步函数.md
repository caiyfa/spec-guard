# 试跑恒 500（Internal Server Error）：asyncio.run 包同步函数 + 试跑产物链全断

> 登记：2026-08-26 ｜ 会话：20260825_151821_3178914e（用户报障）｜ 类型一·事故类

## 现象

工作台草稿产物面板（及草稿评审页）点「▶ 试跑」必败，前端只显示
**「试跑失败：Internal Server Error」**，无任何异常具体信息；
工作区 `.specguard/reports/` 下无任何试跑产物。

## 证据链

1. 端点代码 [routers/drafts.py] trial_run_draft：
   `await asyncio.to_thread(lambda: asyncio.run(_handle_run_scenario({"draft": filename})))`
2. 被调 handler [mcp_server/tools/scenario_tools.py:395] 是**同步函数**
   （`def _handle_run_scenario`，非 async）——`asyncio.run(同步函数返回值)` 必抛
   `TypeError: An asyncio.Future, a coroutine or an awaitable is required`（Python 3.14 措辞），
   未捕获 → Starlette 裸 500。该写法自 K-046（ecb7eea，8 月初）引入，HTTP 试跑入口从未成功返回。
3. 仓库根 `reports/agent_20260803~0807_*` 共 28 个历史试跑目录**全部为空目录**
   （0 文件）——试跑路径从不调 report_writer，run_dir 只 mkdir 不落盘；
   8/7 之后无新目录（工作台多工作区化后试跑在工作区侧更早环节返回，连 mkdir 都没到）。
4. `append_failures`/`append_executions` 全仓仅 runner.py（正式执行 pytest）与
   plan_executor.py（计划执行）调用——试跑路径不进 failures/executions 索引；
   output.log 是 pytest 子进程 stdout 落盘，in-process 试跑天然没有。
   → Agent 排障工具链（attribution: failures/log/report/case/db）对试跑失败**完全失明**。

## 根因

工具链层双缺口：① HTTP 端点误用 asyncio.run 包同步 handler（异步误用，试跑结果永远到不了前端）；
② 试跑落盘面与正式执行不对齐（设计遗漏——run.json/cases/output.log/索引/run_id 五件全无，
Agent 侧无可排查的事实源）。

## 修复

- ① drafts.py trial_run_draft：去 asyncio.run 包装（同步 handler 直接 to_thread），
  全调用加兜底 try → 结构化 `{ok: False, error}`（不再裸 500）；audit 失败不再吞结果
- ② scenario_tools._handle_run_scenario：output.log Tee 双写（console+文件）+
  report_writer.dump_json/render_md 落盘 + failures/executions 索引收录 +
  响应带 run_id（与 plan_executor 同一落盘面）
- ③ 前端 TrialRunResult 加 run_id 字段；DraftArtifactsPanel / Drafts 页试跑结果
  展示任务号 + 「发给 Agent 可排查」提示
- TDD 回归：test_specstd/test_trial_run_persistence.py ×5（先红后绿，首条即
  TypeError 复现钉死原 bug）；test_specstd 相关 85 绿 + engine_modes 39 绿 +
  test_engine 230 绿 + release_check PASS + tsc 零错误（修复变更待提交）

## 预防

- asyncio.run / asyncio.create_task 的参数必须是协程——包装三方函数前先看是 def 还是 async def；
  「同步 handler + to_thread」才是正解，禁止 `asyncio.run(sync_fn(...))`（值先求值、必 TypeError）
- 新增执行类入口时对照 plan_executor 落盘面五件套自查：
  run.json/cases（report_writer）、output.log（调用链）、failures/executions 索引、
  run_id 回传、响应错误结构化——少一件，Agent 排障就瞎一只眼
- 端点兜底：任何 handler 调用层未捕获异常 = 用户只看到 "Internal Server Error"，
  必须兜成结构化错误 JSON 返回（FastAPI 裸 500 无 detail）
- 验收试跑类功能时断言「报告目录非空」（空目录 = 落盘链路断的强信号）
