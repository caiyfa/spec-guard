# 试跑早期失败无任务号——run_id 生成点靠后 + 格式未统一

> 登记日期：2026-08-26
> 关联事故：会话 20260825_151821_3178914e（HI-PERM-001 试跑链，前两批修复见同日另两份经验包）

---

## 现象

- 会话 LINE 166（2026-08-26）：用户试跑 HI-PERM-001 失败，前端只显示「试跑失败：HI-PERM-001.yaml / 错误：草稿解析失败: version 非法: '0.4-debug'」——**无任务号**，把错误贴给 Agent 排障时 attribution 工具链完全无从下手
- 同会话执行期失败（LINE 82/104/149/228/250）都有任务号（agent_2026xxxx）可追——缺口只在**早期失败分支**（装配失败/草稿解析失败/场景不存在/循环依赖）
- 用户诉求原话：「试跑失败的也得有任务号让 agent 会话排查问题」

## 证据链

- `mcp_server/tools/scenario_tools.py` 原 L494：`run_id = "agent_" + strftime(...)` 在 `_setup_runtime`（L452）与草稿解析（L472）**之后**才生成——之前的失败分支只返回错误文本，无 run_id、无落盘
- run_id 格式 `agent_`+时间戳 ≠ 任务号契约 `EX-`+8hex（AGENTS.md 故障排查/K-050）；`plan_executor.py` T-116 注释明确时间戳 run_id 两宗罪：①同秒两次触发目录互覆 ②无 EX- 前缀无法按任务号排错——T-116 修了 plan_executor 但漏了试跑路径
- 执行异常分支（run_error）：`rctx.records` 为空时 dump 的 run.json cases 为空 → `failure_index.append_failures` 收录 0 条 → `list_failures` 查不到执行异常

## 根因

**任务号生成点靠后 + 格式未统一**（实现层，单函数内）：

1. run_id 在一切 fallible 操作（装配/解析）之后才分配，早期失败天然无号无现场
2. 试跑路径沿用时间戳 run_id（K-050 之前 runner 同款问题，T-116 统一格式时未覆盖）

## 修复（2026-08-26，待提交）

- **任务号前置**：参数校验（sid/draft 二选一）后立即 `run_id = _new_run_id()`（EX- 同 runner/plan_executor），run_dir 先建；此后一切失败都回传任务号
- **失败五件套** `_dump_failure_report`：output.log（错误现场+traceback）+ run.json 单 ERROR case（`failure.category` 语义化：draft_parse / runtime_setup / cycle / scenario_not_found / draft_not_found / no_workspace / scenario_root_missing / execution_error）+ report.md 简版 + failures/executions 双索引 + 结构化回传 `{ok, run_id, error, report_dir}`
- **执行异常补录**：run_error 且 records 空 → 最小 ERROR case（category=execution_error）进索引
- **drafts.py 零改动**：纯文本「错误：」→ 400（参数类自解释）；带 run_id 的 JSON → 200（前端 trialResult 统一展示+复制按钮），现有分支天然兼容
- TDD：`TestEarlyFailurePersistence`×3 先红后绿（草稿解析失败/装配失败/执行异常各验五件套+agent 可读）；存量断言 `agent_` → `EX-`
- 历史兼容：既有 `agent_` 目录 attribution 仍可读（RUN_ID_RE 白名单不排除）
