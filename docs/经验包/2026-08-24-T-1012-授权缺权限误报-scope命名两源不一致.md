# 2026-08-24 T-1012 授权「缺 1 项权限」误报 —— scope 命名两源不一致

## 现象

同步设置弹层黄条：「蔡云飞：已绑定但缺 1 项权限，重新授权一次补全」。用户在飞书侧
确认授权已全部完成，重新授权后黄条依旧（误报从 08-18 T-943 落地起即存在）。

## 证据链

1. `do_status('90024166')` / `do_status('90000001')` 实跑：`missing_scopes == ['contactuser:search']`，
   其余 10 项必需 scope 全部命中；
2. 同一 token 的授权全集（`auth status` → `identities.user.scope`，共 200 项）中实际
   存在的是 **`contact:user:search`**（带冒号，飞书官方命名）；
3. 持该 token 直调 `lark-cli contact +search-user --as user --query 蔡 --has-chatted`
   **成功返回 4 个用户**——权限真实具备，决定性证伪「缺权限」；
4. 根因定位 `mcp_server/tools/lark_auth.py` `_REQUIRED_SCOPES` 首项写成
   `contactuser:search`——系 08-18 T-943 照抄网关报错文本
   「missing required scope(s): contactuser:search」（见归档总控 T-941/T-943 备注与
   `test_feishu_pool_page.py` 的报错 mock），与授权清单里的官方命名不一致。

## 根因

**实现层**：scope 名存在两个来源两种写法——网关**报错文本**（`contactuser:search`）与
`auth status` **授权清单**（`contact:user:search`）。必需清单是与授权清单做字符串比对，
却照抄了报错文本的写法，比对永不命中 → 已授权用户恒报缺 1 项。

## 修复

`_REQUIRED_SCOPES` 首项改官方名 `contact:user:search`（45a661e，wt/material-pool 施工、
当日主库验收合并）；TDD 回归 `test_status_contact_scope_canonical_name` 用实测原始
scope 名钉死（先红后绿）；`test_status_missing_and_reviewing` 断言同步改名。
`test_feishu_pool_page.py` 的网关报错 mock **保留原样**（错误透传路径测的是真实网关
消息文本，与授权清单命名两码事）。
验收实证：合并后主库两真实工号 `missing_scopes` 归零；test_specstd 1751 绿 /
engine_modes 39 / test_engine 230 / release_check PASS。

## 预防

- 凡「与外部系统返回清单做字符串比对」的白名单/必需清单，**取值来源必须与比对对象
  同源**——报错文本、文档、清单输出可能是三种写法，照抄报错文本进比对名单是反模式；
- 新增 scope 必需项前先实跑 `auth status` 取授权清单里的原始名（本仓实测快照见
  `test_specstd/feishu_cli_contract.py` 契约fixture纪律同款）；
- 「重新授权后仍报缺」类反馈，先怀疑比对名单而非用户操作——决定性验证=持 token
  直调对应 API 看是否成功；
- 同类排查锚点：`do_status(emp)` 打印 `missing_scopes` + `scopes` 全集比对。
