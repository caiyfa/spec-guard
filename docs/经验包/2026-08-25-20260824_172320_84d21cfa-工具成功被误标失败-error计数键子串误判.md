# 工具返回 ok=true 却被前端标「执行失败」（"error" 计数键子串误判）

## 现象

- 会话：`20260824_172320_84d21cfa`（90024166/人才发展）
- 用户看到：AgentChat 中最后一次 `spec(action=sync)` 工具调用旁显示 ❌ 红叉、tooltip「执行失败，点击查看详情」
- 实际工具执行：成功——`ok: true`、`verdict: PASS`、error 计数 0

## 证据链

1. 会话落盘 `agent/sessions/90024166/人才发展/20260824_172320_84d21cfa.jsonl` 第 42 行（tool 结果）：
   ```json
   {"ok": true, "old_commit": "ed013d7595f3", "new_commit": "e4696441e85f", "changed": true,
    "report": {"verdict": "PASS", "summary": {"error": 0, "warn": 8, "info": 0}, "findings": [...]}}
   ```
   工具协议明确声明成功；合规报告 summary 中 `"error": 0` 是**错误计数为零**（成功信号）。
2. 前端判定 `workbench/frontend/src/pages/agentChat/ToolBlocks.tsx` L95（修复前）：
   ```tsx
   const isError = hasResult && (tool.result!.includes('"error"') || tool.result!.includes('ERROR') || tool.result!.includes('❌'));
   ```
   对结果**原文**做子串匹配，`"error": 0` 的键名字符串命中 `'"error"'` → `isError = true`。
3. 同一误判逻辑共 3 处：L95（单工具块 ❌/✅）、L150（工具组 hasError）、L151（工具组 successCount 统计）。

## 根因

前端展示层环节缺失：工具成败判定用朴素文本子串匹配，未解析 JSON 语义——把「error 计数键名」误读为「有错误」（实现层）。

## 修复

- `agentChat/utils.ts` 新增 `isToolError(result)`：语义分层判定——顶层 `ok` 字段（≠true 判错）→ 顶层 `verdict`（REJECT/ERROR 判错）→ 顶层 `error` 值非空（`Boolean(parsed.error)`，计数 0 不判）→ 非 JSON 对象保留 ERROR/❌ 文本启发式兜底。
- `ToolBlocks.tsx` 三处子串匹配全部替换为 `isToolError()` 调用（与 `groupMessages.ts` 的 `res?.ok === false` 口径对齐）。
- TDD 回归：`agentChat/utils.test.ts` 新增 5 用例（首用例即本会话原始返回体，修复前必红），vitest 106 全绿、tsc 通过、改动文件 oxlint 0 errors。

## 预防

- 前端对工具返回做**状态判定**必须走协议语义字段（`ok` / `verdict` / `error` 值），禁止对结果原文做子串匹配——返回体里任何业务字段都可能撞上启发式关键词。
- 新增/修改工具状态展示时复用 `isToolError`，不另写匹配逻辑。
- 语义判定函数必须有「ok:true + error 计数键」回归用例钉死（`utils.test.ts` 首条）。
- 排障动线沿用：用户报会话 ID → 直接读 `agent/sessions/**/{sid}.jsonl` 的 tool 结果原文，与前端判定逻辑对照，勿凭 UI 表象推断工具成败。
