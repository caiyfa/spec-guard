# 2026-08-19 T-955b AI分类500+图片/附件不可用 · 两处契约错位（mock自证第三案）

## 现象

- 「重新 AI 分类」Internal Server Error（500）。
- 时间轴图片全部「加载失败」；附件点击下载无响应。
- 话题自动聚类从 T-945 上线起产出恒为 0（后台异常被吞，用户无感知）。

## 证据链

1. 本地复现 draft（真实 LLMClient + DB 配置 MiniMax-M3）：
   `AttributeError: 'tuple' object has no attribute 'get'`——`LLMClient.chat()`
   返回 **(message, usage) tuple**，而 topic_cluster 三处（cluster/draft/regen）
   按 `resp.get("content")` dict 消费。测试 mock 恰好返回 dict（mock 自证），
   全绿掩盖生产 500。
2. 实测 `docs +media-download --help`：**不存在 `--media-key` flag**（正确为
   `--token`，且是文档附件通道）——`captions._download_image`/
   `fetch_image_by_key` 旧实现为臆断契约，聊天图片从未下载成功过。
3. 实测 `im +messages-resources-download --message-id --file-key --type image
   --output`：真实下载成功（57KB JPEG，返回 `data.saved_path`）。
4. 附件无响应另一半原因：T-952a 之前落盘的 JSONL 行无 `file_key` 字段，
   前端 `if (!msg.file_key) return` 静默。

## 根因

**跨边界消费未做契约对齐**：①LLMClient.chat 的 tuple 返回 vs 聚类层 dict 消费；
②图片下载臆造 `docs --media-key` flag（聊天图应走 im +messages-resources-download）。
测试 mock 均按消费方期望造形状（mock 自证第三案——前两案见 2026-08-19-T-948 经验包）。

## 修复

- topic_cluster 新增 `_llm_content()`（tuple/dict 兼容提取），cluster/draft/regen
  三处接入；真实 MiniMax-M3 验证产出 2 个话题段（分类链路复活）。
- `fetch_image_by_key` 改 `(message_id, media_key)` 经 im 通道下载（实测 57KB 成功）；
  端点/前端全链路传 message_id（图属消息配对）。
- 前端附件：旧数据无 file_key 显示「需更新后可下载」提示（不再静默）。
- 遗留：`captions._download_image`（图片转述链路）同为臆断契约，聊天图转述需
  imgmap 条目携带 message_id 走 im 通道——下批修复。

## 预防

1. **LLM 消费统一入口**：所有消费 `llm.chat()` 的代码一律经 `_llm_content()`
   类适配层（tuple 契约不再裸消费）。
2. CLI 契约先实测 `--help` 再写调用（本项目第三案，同 2026-08-19-T-948 预防①）。
3. 跨边界调用（LLM/CLI）的测试 mock 形状必须来自真实调用一次的固化产物，
   禁止按消费代码反推。
