# 引用 chip 发送后不清空——每轮消息重复携带并触发后端重复注入

> 会话 20260825_151821_3178914e ｜ 2026-08-25 ｜ 类型一·事故类

## 现象

会话内上传附件（📎 自动建信息包）后，输入区「📦 信息包」chip 常驻不消失；此后**每一条**
user 气泡都带附件 chip，且后端每轮都重新读取附件文件、重建 `<references>` 块注入
user message（模型侧因内容相同有缓存，表现为"没重新读"，但 token 每轮都在重复消耗）。

## 证据链

- `workbench/frontend/src/pages/agentChat/ChatInput.tsx` `doSend`：发送成功（`onSend`
  返回 true）只 `setInput('')`，**`references` state 从不清空**——chip 数据源常驻。
- `AgentChat.tsx` `handleSend`：把 `msgRefs` 挂到每条 user 消息（气泡 chip 渲染，
  L1110-1116）并随 WS `references` 字段每轮发出。
- `workbench/backend/routers/agent.py` `_process_references`：每轮收到 references 即
  重新读文件拼 `<references>` 块（L255/L870），注释明确设计语义为「附件内容**随上传
  那一轮** user message 直接可见」（对齐 OpenAI input_file / Anthropic document block）。
- ChatInput 材料上传处注释同为「随**下一条**消息进 references」——引用本应是
  「随一条消息消费」的一次性载体。

## 根因

前端发送成功路径遗漏清空 `references`（实现层，单点遗漏）——输入框文本清了、引用没清，
与「随当轮消费」的设计语义直接冲突。非后端问题，非会话持久化问题。

## 修复

`ChatInput.tsx` `doSend` 发送成功时 `setInput('')` 同时 `setReferences([])`；发送被拒
（断连/加载中，`onSend` 返回 false）时引用保留，与输入框草稿语义一致。`npx tsc --noEmit`
通过（修复当日落盘，提交号待补）。

不影响面：info_pack 关联（scenarioId）在发送当轮已建立、会话恢复走历史消息 refs
路径，均与 ChatInput 发送后状态无关；材料已入池，chip 仅携带载体。

## 预防

- 「随消息消费」型局部状态（引用/附件/草稿注入）在发送成功路径必须显式清空——新增
  此类状态时把「doSend 清空」列入自检清单；
- chip 类 UI 常驻异常先查 state 生命周期（谁清、何时清），勿先怀疑后端；
- 后端 `_process_references` 每轮全量重读无幂等保护，若未来需要「同一引用多轮复用」
  语义，应改由后端按 sha 去重而非依赖前端清状态（当前语义下不需要）。
