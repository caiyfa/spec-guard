# spec sync 返回体膨胀 50KB（锚点重复消息绝对路径全量拼接）

## 现象

- **会话**：20260824_153425_a3d53352（人才发展工作区，用户指令「拉取最新spec文档」）
- **表现**：`spec(action=sync)` 同步本身成功（e7d86dc42a0e → 9cfee8f1fa67），但返回体被会话层 50000 字符防御截断——工具输出 50KB「大量无效内容：文件路径前缀大量重复」
- 用户附带疑惑：「拉取到了会话目录」——输出中路径均为 `D:\work\tdm-code\specguard-space\specs\...`，被误读为拉取目标不对（实为工作区注册的 local_path，行为正确）

## 证据链

1. 会话消息链（`agent/sessions/90024166/人才发展/20260824_153425_a3d53352.jsonl` 第 5 行）：
   tool content 50052 字符，JSON 解析在 char 50000 断裂（截断切坏转义序列）
2. 内容构成：47 条 conformance findings（46 ERROR + 1 WARN），其中约 40 条 ANCHOR
   「FR-0xx 在多个文件重复定义」——每条 message 把全部**绝对路径**逗号拼接
   （FR-001 一条 28 个文件 ≈ 2KB），且 `detail.files` 把同一份路径清单**再存一遍**（×2 膨胀）
3. 代码链：
   - `specstd/anchors.py` `parse_spec_md` 的 `file_path=str(path)` 是绝对路径
     （契约——`dev_context.py` 等消费方直接 `Path(info.file_path)` 使用，不可改）
   - `specstd/conformance.py` `_check_anchor` 消息 `', '.join(p for p in paths)` 全量拼接
   - `specstd/ws_registry.py` `pull()` 第 442 行无条件 `report.to_dict()` 全量塞进返回体
   - 附带发现：`ConformanceReport.add(..., **detail)` 与调用方 `detail={...}` 冲突，
     所有 finding 的 detail 被多包一层（`detail.detail.files`）——存量实现 bug，无消费方依赖
4. 真实工作区复测（修复前）：check_conformance 输出 33KB+（会话截断前的原始体量更大）

## 根因

面向 Agent 的工具返回体无体量预算（实现层）：sync 语义是「拉取」，却无条件附带
全量合规整改报告；ANCHOR 重复消息又用绝对路径全量拼接且 message/detail 双份存储——
多模块工作区（28 个模块各自 FR-001 本地编号）触发组合爆炸。

（背景：TDM 工作区各模块基线均为 FR-001 起步的本地编号，与 conformance
「FR 锚点全局唯一」规则系统性错配——每次 sync 恒 REJECT 46 ERROR，是既有语义决策项，
非本次输出优化范围。）

## 修复

- `conformance.py _check_anchor`：消息相对工作区根 + 前 5 文件截断 +「等 N 个文件」；
  `detail.files` 全量相对化（程序消费保留全量，AnchorInfo.file_path 绝对路径契约不动）
- `schema.py ConformanceReport.add`：显式 `detail: dict | None` 参数消除 `**detail`
  嵌套 bug（`**extra` 保留旧式零散关键字兼容；全库无消费方按嵌套结构取数，安全）
- `ws_registry.py pull()`：合规自检摘要化——verdict + summary + 前 10 条样本 +
  omitted 计数 + 指路 note（完整报告走 validate 工具/工作台合规页）；
  REST（workspace.py:325）与前端（WorkspacesPanel 只消费 `report.verdict`）兼容
- 回归测试 ×3（TDD 先红后绿）：消息相对化+截断+体量上限、detail.files 全量相对、
  pull 摘要化结构
- 实测（真实「人才发展」工作区 pull 端到端）：**50000+ 截断 → 13846 字符（瘦身 ~72%）**

## 预防

1. **面向 Agent 的工具返回体要有体量预算**：附带类信息（报告/清单）一律摘要化
   （样本 + 计数 + 指路），全量走专门的查询工具；message 内路径列表一律相对化 + 截断
2. **同一份数据不在 message 与 detail 双份存储**：message 给人看（短），
   detail 给程序（结构化全量）
3. 排查「工具输出大量重复内容」类问题先量会话 JSONL 中 tool content 长度与截断点
   （`python -m agent.inspect <sid>` 或直接解析 jsonl），从内容构成入手归因
4. 遗留决策项进展（2026-08-24 同日拍板+实施）：
   - FR 唯一性口径已拍板「模块内唯一」→ 实施为**功能目录边界**（specs/{module}/{feature}/，
     即 TDM 各功能 FR-001 本地起步约定的实际单位；一级模块边界仍会撞 data 模块内
     4 个功能的 FR-001）：跨功能/跨模块同名合法，同文件内重复报错。实施后 TDM
     工作区 ANCHOR 错误 44→0。
   - ANCHOR 噪音消去后剩余 findings 显形（同日三项拍板）：①AGENTS×2（规则错配：
     TDM 用 '## OVERVIEW' 不匹配 'Project Overview' 正则；无术语节）——**拍板暂不
     处理**，错误继续显示；②API_LINT×8（**TDM 文档真实 YAML 语法错误**：7 个
     api.yaml 的 title 行含未引号 `|` 且 title/version 同行，1 个行尾多余 `}`）
     ——**拍板只记录不修**，留给 TDM 维护流程；③STRUCT×7（delta 必备文件错配）
     ——**拍板降级 WARN**（同 T-1000 缺失类不阻断先例）：SpecGuard 不强推三件套
     模板，缺件不再 REJECT、不再卡 delta_committer 受限提交门禁。
   - 三项落地后 TDM 工作区终态：19 findings = AGENTS×2 ERROR（保留）+ API_LINT×8
     ERROR（保留，真实缺陷）+ WARN×9；verdict 仍 REJECT（用户知情选择）
