# 2026-08-27 · T-1033 守卫指纹竞态——纯读误伤与覆盖面收窄

## 现象

- test_specstd 全量偶发**单例失败**且受害例随套件组成漂移：全量挂在
  `test_agent.py::TestMaterialE2E::test_upload_reference_read_material_chain`，
  换四文件组合则换成 `TestRuntime::test_tool_execution`（报错形态为
  `json.loads` 在第 1 字符即抛 JSONDecodeError）。
- 失败时工具返回被整体替换为 `[SIDE_EFFECT_VIOLATION] 纯读工具 pack 产生了
  副作用…`，并非用例逻辑断言失败。
- 基线树（同码 9624be5）全量绿；本树反复稳定复现——「环境感」极强。

## 证据链

1. 组合实验：单跑/前缀跑均绿，仅特定套件组成下失败，且受害例漂移（时序型信号）。
2. 指纹采集插件（临时 pytest 插件镜像 `_take_snapshot_fingerprint` 采集逻辑落盘
   parts）跑四件套：20 次快照的相邻差分中，**唯一变化项全部是
   `workbench/backend/data/workbench.db` 的 size(+4KB)/mtime(跳秒)**，其余覆盖面零变化。
3. 因果实验：把真库移开→四件套全绿；给指纹采集加毫秒级延迟→无库全量跑出满额
   1954 绿 6 跳（窗口被错开）；库文件还原→失败复现。
4. 静置观察：库文件在套件结束后即稳定——写者是测试进程自身的 SQLite WAL
   checkpoint 异步刷盘（前序审计写入的滞后落盘），并非外部进程。

（位置：agent/runtime.py `_execute_tool` 的 none 级 pre/post 指纹比对；
 `_take_snapshot_fingerprint` 旧版覆盖 specs/scenarios/agent-skills/
 mcp_server-tools/drafts/feedback + ws 区 + **workbench.db/ledger/registry 三运行态文件**。）

## 根因

**守卫设计层**：T-081 副作用守卫把「SpecGuard 整体不可变」当作覆盖目标，将运行态
文件纳入指纹面；运行态文件的异步落盘（SQLite WAL checkpoint）与本工具执行无关，
却落在前后指纹的毫秒级窗口内，守卫无法区分写入者，一律记到当前纯读工具头上——
误伤。测试全量只是把这一固有窗口碰撞放大成高频事件（套件节奏决定命中率）。

## 修复

- T-1033（用户拍板）：守卫语义收窄为「纯读工具不得写**用户工作区文档**」——
  `_take_snapshot_fingerprint` 只覆盖工作区产物（私有区+共享区，specguard_dir），
  仓库六个目录与 workbench.db/ledger/registry 三运行态文件全部移出指纹面；
  无工作区上下文时返回恒等指纹（无面可守）。
- 防回潮双钉（test_skill_governance.py）：源码钉剥离 docstring 后断言运行态/
  仓库面字面量不得出现在指纹代码体；行为钉验证「仓库/运行态变化不动指纹、
  工作区改写/新增必动指纹」。
- 本文件即登记；总控 §4 T-1033 行与 T-1029 行注记闭环。

## 预防

- 「某纯读工具被判副作用」排查时，先问**指纹窗口内还有谁在写**（审计落库、
  watcher、调度器），再怀疑被测工具；用差分指纹插件一跑即知。
- 运行态文件（任何 *.db / json 台账 / 日志）不得进入断言性快照/指纹面；
  运行态完整性由各自写通道与发布闸门负责。
- 新增目录进守卫指纹面前，必须论证该面内不存在异步写入者（或写入者可控 quiesce）；
  守卫类测试钉覆盖面时用「行为双钉」而非仅源码字面量。
