# 2026-08-26 agent_20260826_112426：python 原语三连败与试跑报告读写错位（Agent 排障失明）

> 关联任务：T-1016 / T-1017 / T-1018 / T-1019（wt/engine-hardening）
> 触发：Agent 会话 20260825_151821_3178914e 为 HI-PERM-001（权限场景）试跑连续失败 3 次后产出事故报告，总控人转交引擎侧复盘。

## 现象

1. HI-PERM-001 试跑三连败（任务号 agent_20260826_112426 / 112704 / 113207）：
   - `NameError: name 'roles_resp' is not defined`
   - `AttributeError: 'str' object has no attribute 'get'`
   - `TypeError: HttpClient.request() got an unexpected keyword argument 'json'`
2. Agent 按 debug-failure 技能调 `attribution(action=report/case)` 排查，三次均返回「运行报告不存在」——**排障工具链对自己刚跑的试跑完全失明**，只能盲猜结构，导致第二、三次修复方向错误。
3. Agent 事故报告的根因分析部分失真（推测「ns 结构未知」「假设 {status,json,headers} 被反驳」），拟写的修复文档 §5.1/5.2 与引擎实现**事实相反**（若照单采纳会把错误知识写进规范）。

## 证据链

- `{workspace}/.specguard/90024166/reports/agent_20260826_112426/cases/HI-PERM-001.json`：`saved_vars.roles_resp` 落盘为 `{"status": 404, "json": {...}, "headers": {...}}`——call save 结构就是 `{status, json, headers}`，与 `engine/scenario_runner.py:step_call` 返回值一致（假设1并未被反驳）。
- `agent_20260826_112704` 同位置：`roles_resp.json` = `{"status":"404","message":"NOT_FOUND","data":"NOT_FOUND"}`——**端点 404**，`data` 是字符串；第二次 AttributeError 是脚本对 `json.data`（str）继续 `.get()` 导致，与 ns 结构无关。
- 会话 JSONL（`agent/sessions/90024166/人才发展/20260825_151821_3178914e.jsonl`）：attribution 报「运行报告不存在: agent_20260826_112704」，而报告实际存在于 `.specguard/90024166/reports/`（**emp 私有区**）。
- 代码对账：`mcp_server/tools/scenario_tools.py` 试跑落盘用 `specguard_dir(workspace_root=ws.root)`（无 force_shared → emp 上下文落私有区）；`mcp_server/tools/attribution.py:_get_reports_root` 走 `reports_dir()`（T-014 起强制共享区）。写私有、读共享 → 错位。
- `engine/http_client.py:HttpClient.request` 签名为 `json_body=`（内部透传 requests 的 `json=`），无 `json=` 别名。

## 根因（哪个环节缺失）

1. **工具链层（主根因）**：08-26 晨试跑落盘功能（2097591）写报告用 `specguard_dir()` 未 `force_shared`，emp 上下文（Web 登录态/Agent 会话恒有）下落 `{emp}/` 私有区；attribution/索引统一读共享区——与 T-014（reports_dir）、T-1011（specflow_dir）同根因形态第三次复发。**注释里写明的意图（"attribution 工具链可排查"）从未在 emp 上下文下验证过**——测试未覆盖「emp 上下文 + 写后同口径读」组合。
2. **文档层**：format_spec §1.13 未明示「script 不渲染 `{{}}` 插值、save 变量不是脚本全局变量」，未给出 ns 结构与 http(account) 签名（save 结构其实在 §1.6 产出变量列有，缺 python 侧的桥接说明）。
3. **引擎 API 层**：HttpClient JSON 参数名 `json_body=` 与 requests 肌肉记忆（`json=`）不符。
4. **场景/Agent 侧（非引擎责任）**：Agent 臆造了不存在的 hr-center 端点（三次均 404），且未先判 status 再钻取响应体。

## 修复

- **T-1016**：`scenario_tools.py` run_dir 改走 `reports_dir()`（强制共享区，与 attribution 同落盘面）；**波及面同修**：`sg_core/spec_baseline.py:_baseline_path` 补 `force_shared=True`（签名基线=工作区级共享资产，emp 上下文下误落私有区会让每用户各自建基线、spec 变更检测对 Web 用户静默失明）。回归测试：emp 上下文试跑→attribution 可读（test_trial_run_persistence）+ emp 上下文基线路径归共享区（test_spec_baseline）——均先红后绿。
- **T-1017**：format_spec 2.14.0→2.15.0 三同步：§1.13 补「插值边界」+「五类 save 产出在 ns 中的结构表」；新增 §1.13.1 http(account) 完整签名与「常见错误对照」表；修正断言语义归类 CAT_SCENARIO（原文档 CAT_ENV 滞后于 ENG-T01）；快照 docs/specguard-yaml-format-spec.md 重导出。**未采纳**事故报告 §5.1/5.2 的错误写法（ns 平铺 key / foo.text / "json= 已支持"均与实现相反）。
- **T-1018**：python 步骤/断言脚本 NameError/KeyError 时错误消息附「ns 当前可用键清单 + 正确访问范式」（`_ns_hint`），让 Agent 一轮自愈。
- **T-1019**：`HttpClient.request`/`post` 兼容 `json=` 别名（与 `json_body=` 同义，同传报 ValueError）。

## 预防

- **目录解析纪律**：工作区级天然共享产物（reports/索引/基线/info_packs）一律 `force_shared=True`（或走 reports_dir/info_packs_dir 门面）；新增写路径时对照检查读者落盘面。
- **测试纪律**：凡「emp 维度目录解析」的读写对，测试必须覆盖「设置 emp 上下文 → 写 → 用读者同口径读」闭环（T-014/T-1011/T-1016 三连发的共同缺口）。
- **事故报告纪律**：Agent 产出的根因分析须与落盘证据（saved_vars/case JSON）对账后再采纳；本次若直接采纳其拟写文档会引入反向错误。
- **引擎新能力**：文档（format_spec）与 API 签名同步给出最小可运行示例；错误消息尽量附上下文（ns 键清单模式可推广到其他 exec 面）。
