# git 对象库清空：提交链丢失、分支 ref 消失——全量恢复复盘

> 2026-08-20 ｜ 类型：仓库基础设施事故（非代码缺陷）｜ 恢复提交：36f8108

## 现象

多会话并行开发期间（2026-08-20 下午），主库 git 全面不可用：

- `git status` → `fatal: bad object HEAD`
- `git log` → `fatal: your current branch 'feature/T-948' does not have any commits yet`
- `git fsck` → `missing blob` ×31 + `error: … invalid sha1 pointer in cache-tree of .git/index` ×5
- 并发观测异常：HEAD 所显分支在 `feature/ENG-T01`（unborn，全文件暂存）与 `feature/T-948` 之间来回跳变——其他会话正在同一 `.git` 上切分支

## 根因

`.git/objects` 对象库被整体清空（触发机制不可考，证据链 #1/#7），叠加并行会话删除分支 ref（#2/#4），构成「历史不可解析 + HEAD 悬空」的复合故障；index 与工作区未受影响，为全量恢复提供了内容基础。**环节归属：环境/仓库基建**（多会话共享单一 `.git` 的脆弱性），非引擎/场景/配置缺陷。

## 修复（四步，全部只写 `.git`，零工作区文件改动）

| 步骤 | 动作 | 要点 / 坑 |
|------|------|----------|
| 1 | `git fetch origin` | 拉回 master@fbc53da 全量历史（293 提交，5.7MB pack）。只增对象与 `refs/remotes/origin/*`，对并行会话安全 |
| 2 | `git hash-object -w -- <32 文件>` | 重建 index 引用但对象缺失的暂存 blob。**坑：普通 `git add` 对「内容未变」文件不重写 blob**（它信任 index 里已有的 SHA），必须 `hash-object -w` 无条件写入 |
| 3 | `git update-ref refs/heads/feature/T-948 fbc53da…` | 重建被删分支 ref（取删除前 ref 文件原值 = 远端 master tip） |
| 4 | `git write-tree` | 按当前 index 全量重算并写入 tree 对象，使 index cache-tree 中 5 个指向已丢失 tree 的过期指针**按原 SHA 复活**。不清除的隐患：下次 commit 若子树 stat 未变，git 会直接复用不存在的 tree SHA 产出坏提交 |

验证：`git fsck` 全干净；index blob 缺失复查 0；`log/status/diff/diff --cached` 全部可用。提交前门禁：`release_check` PASS、`engine_modes` 39 过、`test_engine` 152 过；恢复性全量入库 36f8108（48 文件 +6347/-432）已推送 `origin/feature/T-948`。

## 预防（可执行清单）

1. **提交即推（备份线纪律）**：worktree 与主库共享同一对象库，本地对象不是备份，远端是唯一提交细节备份线。任何会话完成一次提交立刻 `git push`——本事故中未推送的 T-948→T-955b 提交链（~10+ 提交）即因此永久丢失边界与 message。
2. **完整性自检命令**（建议挂 pre-push 或每日例行）：
   ```
   git fsck --no-progress          # 出现 missing/invalid 即按本案例四步恢复
   git count-objects -v            # 对象数骤降（如 <100）= 清空信号，立即 fetch
   ```
3. **恢复路径速查**（按症状对号）：
   - 历史不可解析 → `git fetch origin`（对象在远端）
   - 分支 ref 消失 → `git update-ref refs/heads/<分支> <原值>`（原值查 `git ls-remote` / 并行会话记录）
   - 暂存 blob 丢失 → `git hash-object -w -- <文件>`（**不要用 `git add`**）
   - cache-tree 过期指针 → `git write-tree`
4. **多会话并行基建**：优先每会话独立 clone / `git worktree`；共享单工作区 + 单 `.git` 时 HEAD 唯一（一个会话切分支全体跟跑——本事故的 orphan `feature/ENG-T01` 事件即前兆），且对象库一毁全毁。
5. **破坏性 git 操作互斥**：多会话共用仓库时禁止并发 `git gc` / `prune` / `reset --hard` / `branch -D` / `checkout --orphan`；需要孤儿分支/干净树的场景一律走 `git worktree add`。
