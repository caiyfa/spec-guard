# 站内协作设计单：讨论消息源接入话题流水线（不重做飞书）

> **定位**：新功能域（建议编号 **M-G 站内协作**，或挂 M-E 后续）。让研发/测试/产品在 SpecGuard 站内围绕被测系统讨论需求/bug/方案，讨论**复用现有话题流水线沉淀**（聚类→话题卡→图谱→反查），不另起一套 IM。
> **边界（拍板已定）**：站内协作 ≠ 重做飞书——不做实时群聊/在线状态/消息推送/@提醒全套 IM；只做「讨论消息源」+ 复用话题沉淀机制。飞书群聊仍是主 IM，站内讨论是**被测系统语境下的结构化补充**（挂 FR/工作区/材料，可沉淀可反查）。

---

## 背景与动机

现状：话题/材料是**飞书群聊专用管道**——消息来源只认 `chats/{chat_sha8}/{yyyymmdd}.jsonl` 群快照（飞书 CLI 拉取），话题卡 id `tp:{chat_sha8}-{day}-{seq}` 绑群，站内无任何讨论通道。

痛点：讨论需求/bug/方案得切到飞书群，结论散落在群消息里找不回；想在被测系统语境（挂 FR 锚点/工作区/材料）下边测边聊没有地方。

目标：研发/测试/产品在 SpecGuard 站内直接讨论，讨论消息**像群聊一样进话题流水线**——聚类成话题卡、入图谱、可反查，与飞书群聊同权沉淀。

## 方案设计：讨论消息源接入（最小改动复用流水线）

### 核心抽象：讨论 = 一个「虚拟群」

不新建消息机制——**站内讨论落 chat_store 同款 JSONL 快照**，用一个固定来源标识作虚拟群的 chat_sha8（如 `discuss` → sha8 派生），让话题流水线把站内讨论当成「一个叫『站内讨论』的群」来消费。**改动集中在「消息从哪来」，话题机制本体零改动。**

### F1 讨论消息模型与快照（后端）

- **消息模型**（轻，落 workbench.db 或 JSONL 直接写）：`{disc_id, parent_id(回复), author_emp, author_name, content, created_at, fr_anchor?, workspace, edited_at?, deleted?}`
  - 支持**回复**（parent_id 线程）与 **FR 锚点挂载**（可选，讨论挂需求/场景，接 product_index 反查）
  - 编辑/删除留痕（改原行 + 历史，对齐 chat_store「同 id 覆盖刷新」语义）
- **快照落池**：讨论消息写入即落 `chats/{disc_sha8}/{yyyymmdd}.jsonl`（chat_store 既有 `evt:` 前缀模式扩展——message_id 用 `disc:{disc_id}`），`.md` 派生视图由 chat_store 既有逻辑重建。**聚类/watcher 像感知群快照一样感知讨论快照**。
- **诚实语义**：消息仅在站内产生（无外部同步源），不存在「拉取/幂等合并」——写入即事实源，天然幂等。

### F2 讨论区 API（后端新路由 `routers/discuss.py`）

- `POST /api/discuss/messages` 发消息（登录即可；body: content/parent_id?/fr_anchor?/workspace）
- `GET /api/discuss/messages?workspace=&fr_anchor=&day=&parent_id=` 拉消息（按工作区/FR/日期/线程过滤）
- `PUT /api/discuss/messages/{id}` 编辑（仅作者；留痕）
- `DELETE /api/discuss/messages/{id}` 删除（仅作者/admin；软删留痕）
- RBAC：登录即可发/读自己工作区的讨论（复用 T-1000 工作区可见范围）；admin 可管全部
- **审计**：user_store.audit 记 discuss_post/edit/delete

### F3 讨论区前端（轻，不做 IM 界面）

- **讨论面板**（新组件 `DiscussPanel.tsx`，可挂话题工作台侧 / 场景详情页 / FR 锚点处）：
  - 消息流（按时间倒序，线程缩进展示回复）+ 输入框（可选挂 FR 锚点）
  - **不做**：实时推送、在线状态、未读角标、@提醒——刷新即拉取（轮询可选，默认手动刷新，对齐「不做 IM」边界）
  - 三态分离（加载/空/错误）+ 长操作可单点刷新（体验基线③④）
- **话题工作台**：useChatOptions 增加「站内讨论」虚拟群选项（source=discuss），话题卡/跨群关联/图谱对讨论来源天然可见（chat_sha8=disc_sha8，与飞书群并列）。

### F4 话题流水线接入（零改动验证）

- 聚类 `_cluster_once` 扫 `chats/` 时自动包含 `disc_sha8` 目录——讨论消息参与聚类，产出话题卡（category 走五分类：需求讨论→requirement、bug→test/solution、方案→solution，闲聊→chat 默认过滤）
- `facts._TOPIC_KEY_FIELDS`/图谱 relates 边对讨论话题天然生效
- **验证点**：发几条讨论 → 触发聚类 → 话题工作台出现「站内讨论」来源的话题卡 → 图谱可查

## 明确不做（边界，防 scope 蔓延）

- 不做实时推送/WebSocket 在线状态/未读角标/@提醒（那是 IM，刷新即拉取即可）
- 不做讨论@飞书双向同步（飞书群聊与站内讨论是**两个独立消息源**，各自进话题流水线，靠话题机制在图谱层汇合，不做消息层互通）
- 不做讨论内容的 LLM 转述/聚类之外的额外加工（复用现有聚类，不新增评估器）

## 待拍板项

1. **讨论的组织粒度**：按工作区（每工作区一个讨论区）还是按系统（每系统一个）还是全站一个？——倾向：**按工作区**（对齐 T-1000 自管理与可见范围，讨论贴近 spec 语境）
2. **讨论面板挂点**：独立一级菜单「讨论」，还是挂话题工作台/工作区中心页签？——倾向：先挂**话题工作台侧 + 场景/FR 详情处**（讨论贴着被测对象，不单列菜单）
3. **是否支持富文本/附件**：纯文本起步，还是支持 md/图片？——倾向：**纯文本 + md 起步**（附件走材料池既有上传，不在讨论里重做）
