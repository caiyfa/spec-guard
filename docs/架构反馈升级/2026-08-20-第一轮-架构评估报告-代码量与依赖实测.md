- **清晰部分（自底向上单调）**：engine 绝对纯净（零上层、零 systems 硬编码）；systems→engine 单向注册表反转，教科书式插件架构；specstd 零依赖属实；feedback/integrations 干净叶子包；workbench routers→services 严格单向（0 反例）。

## 三、七个扩展点实现摸底（含 file:line 证据）

### 3.1 注册表模式（engine/registry.py + tool_registry.py）——✅ 干净

双注册表：运行时 `Registry`（registry.py:9-45，三张 dict：step_handlers/oracles/data_providers，`get_*` 带已注册清单的 KeyError 自愈）；元数据 `TOOLS`（tool_registry.py:22-37，模块导入时注册、重复抛 ValueError，:40-58 动态生成 format_spec tool 目录=单一真相源）。装配点 conftest.py:117-121：先 register_builtin_steps/oracles，再 `importlib.import_module(f"systems.{sg_system}")` 调 `mod.register(reg, env_config, db)`；systems/tdm/__init__.py:6-25 完成三类挂载；tdm/steps.py:20-82 导入时注册 tool 元数据、:384-390 绑定 handler，由 step_tool 分发器按 name 关联（scenario_runner.py:610-627）。

**"引擎层零改动接新系统"结构上成立**（接新系统 = 新增子包 + SPEC_GUARD_SYSTEM）。⚠️ 三处坏味道：① 引擎默认值泄漏 TDM 语义——`http_client(account, service="tdm")`（scenario_runner.py:126）、`default_resource_code: "TDM_SNAPSHOT_ARCHIVE"`（:120）；② HR 领域中文词库 `RANDOM_POOLS` 硬编码在通用引擎（:521-549）；③ 属"约定式最小插件"而非完整插件架构（无 manifest/无版本/单次运行只挂一个系统）。

### 3.2 引擎核心（engine/scenario_runner.py，1258 行）——⚠️ 上帝模块迹象但组织良好

`RunContext`（:98-174）session 级上下文（registry/env/graph/dbs/leases/instances/teardown_stack/shared_ns + http_client 服务路由工厂 :125-160）。调度链：`run_with_deps`（:1136-1191）→ `_check_dep_versions`（:1103-1133）→ `_resolve_dep_ns`/`_acquire_instance`（:1037-1078，shared 复用/exclusive 懒重跑实例池核心）→ `run_scenario`（:918-1004，flow 循环 + `_run_verifies` :780-911 + 异常→verdict 映射）；`run_teardowns` LIFO（:1220-1258）。与 dependency_graph.py 分工清晰：graph 静态建图/环检测/拓扑，runner 运行时实例/租约/teardown。

坏味道：① python exec 上下文构建重复两份（step_python :672-684 与 python 断言 :879-890）；② run_with_deps 尾部共享实例登记与 _acquire_instance :1074-1077 逻辑重复（:1183-1190）；③ 全文件 `print()` 当日志（:278、:953）；④ 适配包在 rctx 上猴补 `_hr_oracle` 属性（tdm/steps.py:141-142），契约外接触引擎内部对象；⑤ run_single（:1198-1213）零增量抽象。

### 3.3 适配层（systems/tdm，1294 行）——契约面形式小、隐式约定撑大

config.py:57-95 `load_env` 三层：`systems/_shared/config/env.{env}.yaml` 打底 → 本系统 yaml 同键覆盖（_shared/__init__.py:51-55）→ `_substitute` 递归替换 `${VAR:default}`（:25-39）→ DB 密码回退链 SG_DB_PASSWORD_{SCHEMA} → SG_DB_PASSWORD → 个人 devops 凭据文件（:69-93）。emp_pool.py 76 行 / queries.py 121 行只读 SQL 库 / hr_center_oracle.py 97 行权限预言机 fail-secure。

隐式契约：env 键必须按 `{service}_base` 命名（scenario_runner.py:137 约定）、rctx 属性（dbs/leases/token_provider）被适配包触碰。⚠️ ① 硬编码个人机器路径 `~/.qoder/skills/devops/scripts/.env.devops`（config.py:16）；② **SIT `internal_token.client_secret` 明文提交进仓库（env.sit.yaml:40 附近）——安全问题**；③ `${VAR:default}` 解析逻辑 config.py 与 _shared/__init__.py 各写一份。

### 3.4 薄 Harness（agent/runtime.py，901 行）——循环核心薄，外延塞太多

主循环 `AgentRuntime.run`（:391-564）：组消息 → 恢复 JSONL 历史 → llm_messages 工作副本（K-019 压缩只作用它）→ 每轮取消检查（:449）→ should_compact/compact → llm.chat（SSE）→ 顺序执行 tool_calls → 足迹事件 → 增量落盘 → for-else 熔断。工具分发 `_execute_tool`（:676-787）：todo_write meta 拦截 → 三层白名单（`resolve_tools` :144-166 = 全注册 ∩ purpose ∩ RBAC）→ tool_map 定位 → `asyncio.run(mod.handle(...))`（:770）→ side_effect 指纹校验（:789-830）→ 审计。

**"薄"名不副实**：70+ 行硬编码 RBAC 工具清单（:59-118，需与 29 个工具模块手工同步）+ 知识 nudge/经验飞轮检索（:574-639）+ 目录指纹副作用警察 + 审计 + 截断落盘。最重坏味道：跨层直连 services（:600 experience_store、:715 user_store，靠运行时 sys.path 插入 :712-714）；每次工具调用 asyncio.run 新建事件循环（:770）。

### 3.5 MCP 工具层（mcp_server/，8,281 行）——单一注册点正确，规模越临界

server.py:61-107 `build_tool_modules()` 是单一注册函数（T-602，runtime 与 stdio server 共用防双写漂移）：23 个 tools/ 模块 + 5 个 open/ 模块（对外只读面）。每模块统一契约 `TOOLS=[Tool(...)]` + `async handle()`。live_registry.py:23-55 按需离线重建活注册表（importlib 导入 systems.{system} → mod.register(reg, env_config, None)，失败降级 None）——query_registry/validator 永不与真实注册漂移（D3 决策）。

⚠️ ① **规模失控的文档漂移**：server.py:7 docstring 写"10 个工具"，实际约 29 模块 92+ 工具（AGENTS.md 写"8 模块 24 工具"也已过时）；② 每个工具模块重复 sys.path 样板（29 处）；③ side_effect_registry.py:14 顶层反向依赖 server 靠懒加载避环；④ side_effect 用 `_KNOWN_WRITERS` 手工清单（:31-69），**新增写工具忘登记会被当纯读执行——安全隐患**。

### 3.6 specstd 工作区（specstd/workspace.py，1096 行）——contextvar 最讲究，职责过重

两个 contextvar `_CTX_WORKSPACE`/`_CTX_EMP_NO`（:52-59）+ set/reset token 对，由 workbench 纯 ASGI `WorkspaceContextMiddleware`（main.py:47-67）注入 X-SG-Workspace header，asyncio.to_thread 复制 context 使 agent/MCP/covers 全链路可读。`get_active_workspace` 三级解析（contextvar → SG_WORKSPACE → registry active，:246-263）。registry.yaml 读写带 RLock + 临时文件原子替换（:47、:215-224）；`register_git` 用 `git clone --branch ... --` 防 url 注入（:393-398）；`_emp_subdir` 防穿越净化（:649-667）。

## 四、对照业界设计模式的评估

| # | 本仓模式 | 业界对照 | 判定 |
|---|---------|---------|------|
| ① | 注册表 + 导入时元数据注册（engine） | Registry 模式核心要求：核心不认识插件、插件自注册 | ✅ 达标；format_spec 动态生成消灭文档漂移是亮点；差距：约定式最小插件（无 manifest/版本），当前规模下取舍合理；TDM 泄漏伤纯度 |
| ② | engine=核心 / systems=适配器 / YAML=端口 | 六边形架构（端口与适配器）依赖全部向内 | ✅ 方向正确；端口未形式化：env 键 `{service}_base` 隐式约定、rctx 属性被触碰、猴补 `_hr_oracle` |
| ③ | 双层 YAML（doc 层给人 + flow/verify 给机器）+ SKIP 诚实降级 | MSDN 数据驱动 harness 分类；Zerocode/Maestro 同型；covers+契约版本指纹≈自研消费者驱动契约（Pact 变体） | ✅ 成立；SKIP 语义超越多数框架 |
| ④ | ReAct 循环 + 三层白名单 + side_effect 指纹 | 业界共识：harness 负责校验/鉴权/执行，模型永不直接执行工具 | ✅ 循环设计达标；"薄"名不副实：策略横切关注点应外置；asyncio.run 每调用新建循环是权宜 |
| ⑤ | MCP 单一注册函数 + live_registry | MCP 官方：工具确定性排序、激进分组；AWS/Itential：工具数量失控稀释选择准确率 | ⚠️ 92+ 工具已越临界；`_KNOWN_WRITERS` 手工清单有安全风险；文档漂移严重 |
| ⑥ | FastAPI routers→services 单向 + 依赖注入 | FastAPI 官方大型应用指南 + zhanymkanov 最佳实践 | ✅ 分层达标；坏味道：装配三处复制、user_store 上帝 service、私有成员跨 import、弃用 API |
| ⑦ | contextvar 请求级透传（specstd） | — | ✅ 全仓最讲究的实现；workspace.py 职责过重 |

## 五、总体判断

**架构整体合理，设计纪律高于平均水平。** 核心证据：冻结引擎 + 注册表插件注入 + 零依赖 specstd 底座 + contextvar 全链路透传 + 格式规范单一事实源 + 诚实 SKIP 语义——每一项架构声明经实测全部属实，且都能在业界模式上对上号。

**结构债集中在"应用层三角"（agent ↔ mcp_server ↔ workbench.services），而非引擎。** 三组循环依赖、三份装配复制、三处手工策略清单、引擎内 TDM 泄漏、前端上帝文件、env.sit.yaml 凭据明文——这些是明确可执行的优化标的。

一句话：**底座是教科书的，中上层是"能跑但互相缠绕"的——优化不在于推倒，在于把倒挂的依赖翻正、把复制的装配归一、把硬编码的清单变成派生。**
